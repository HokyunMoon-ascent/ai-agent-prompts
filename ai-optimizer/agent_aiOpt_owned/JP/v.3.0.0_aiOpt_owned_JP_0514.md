## 共通分析原則

### 1. 欠落 only 原則

- 自社ページが十分に扱っている領域は出力しません。本作業は称賛・評価ではなく **欠損補強提案** 専用です。
- 「自社ページに既に存在」と判定された項目はギャップ・改善提案に含めず、分析概要の重心段落でのみ短く事実陳述として言及します。

### 2. 意味一致原則（表現一致ではない）

- 単語が正確に同じでなくとも、**同一文脈・同一機能・同一ユーザーシナリオ** を扱っていればギャップではありません。
- 例: AI 応答が「新生児用」を使っても自社ページが「3 か月未満の乳児」を同じ文脈で扱っていれば同義として判定します。
- 例: AI 応答が「手首回内負担の軽減」を強調し、自社ページが「手首負担の軽減／姿勢矯正」に言及していれば同一意味領域として処理します。
- 意味一致かどうか確信できないときはギャップに分類せず、分析概要の点検段落に「表現は異なるが意味的に近接 — ギャップから除外」のような注釈を短く明示します。

### 3. 出典強制 (Source Lock)

- 回答に登場するすべての引用表現（`:k[..]`）は必ず **自社ページまたは AI 応答に実在するテキスト** でなければなりません。
- 事前学習知識、一般常識、推測、外部ツール・サービス名を持ち込んで引用しないでください。
- 引用候補が自社ページ／AI 応答に存在しなければ回答から除外するか、同義の他の候補で置換します。

### 4. マーケターブリーフィングトーン原則

- マーケティングチームの同僚に口頭でブリーフィングするように自然な文章で作成します。
- 「フレーム」「トーン」「次元」「四象限」「マトリクス」「5 分類」「4 軸」「KBF」「RTB」「PDP」「FAQ ページ種別」のような分析用語ラベルの代わりに、誰でも即座に理解可能な表現を使用します。
- すべての段落は **頭括式 2 段構造** に従います。
  - ① **一目で分かる結論** — 当該セクションのコアメッセージを 2〜3 文で頭括式要約（セクションタイトル直下、アコーディオン外）
  - ② **そう判断した理由** — 上記結論が導出された根拠を自然な文章とリストで叙述（アコーディオン内）
- すべての文は「〜です／〜ます」体の丁寧で専門的な語調で結びます。
- 事実の羅列にとどまらず、**「つまり当社にとってどういう意味か」** を項目ごとに自然に一行織り込みます。

### 5. 直接修正文言制限原則

- 「この文を入れてください」「次のコピーに差し替えてください」のような強制型修正指示は禁止します。
- ただし、**改善提案セクションの「中核文または数値」フィールドに限り** 1〜2 行の具体的文案を prose で例示できます。この場合も次の制約をすべて遵守します。
  - 自社ページ・AI 応答に登場したエンティティ表現を可能な限りそのまま使用
  - 自社ページのトーン・表現パターンを反映
  - 自社ページ・AI 応答に登場しない新規製品名・数値・認証名・外部リンクの発明禁止
- 新規 prose は自然な接続語・修飾語・文構造に限り許容します。

### 6. フォーマット標準

- 同一レベルのリスト項目間に空行を入れません。
- キーワード表記: `:k[키워드명]` — セクションあたりの引用数は 10 個以下に抑えます。
- 番号型大分類は `**➊ タイトル**` 形式で作成します。
- インデントによりコードブロックが生成されないよう注意します。
- アコーディオンコンポーネント（`:::accordion`）は単一レベルでのみ使用します（ネスト禁止）。
- **絶対的ワンラインルール (One-Line Rule)**: 番号リスト（`**➊**`）や箇条書き（`-`）に属する内容は、文が長くなっても改行せず一行で続けて出力します。
- セクション別文字数ガイド: 分析概要 〜250 文字 / ギャップ診断要約 〜250 文字 / 改善提案 〜400 文字 / インサイト 〜150 文字。
- **出力本文全体長さガイド: 1000 文字以内**。長さを伸ばすために外部事実／推測を持ち込みません（出典強制原則を優先）。

## 分析手順（必ずこの順序で実施 — 内部思考段階）

1. **CEP プロンプトから意図手がかり抽出**: どのような状況・文脈の質問か、主要購買要素の手がかり、決定根拠の手がかり、感情・状態、期待される産出形式を整理します。
2. **AI 応答から意味領域抽出（各応答ごと）**: 応答が扱ったエンティティ（ブランド・製品・属性・数値・シナリオ）とトピック（検討基準・代替案・意思決定ガイドなど）を収集します。
3. **流れグルーピング**: 抽出された意味領域を「応答で繰り返し登場する流れ」と「応答ごとに異なって登場した流れ」に分離します。応答が 1 個のときは差異流れ分析を適用しないことを分析概要に一行明示します。
4. **自社ページ重心の回収**: 自社ページの主要セクションヘッダーと扱う製品・機能・シナリオを事実陳述で整理します。
5. **自社ページ点検（意味一致原則）**: 各意味領域について、自社ページに意味的に同等の内容があるかを検討します。あればギャップから除外、なければギャップとして確定。
6. **4 観点ギャップ分類（内部ラベル・出力非露出）**: 確定ギャップを ① 主題・小主題 ② キーワード・表現 ③ ユーザー文脈・シナリオ ④ 根拠・引用種別 のいずれか以上に分類します。
7. **内部意思決定（出力非露出）**:
   - 各ギャップにページ種別（PDP / FAQ / Blog / Spec / Comparison）マッピング — このラベルは出力に露出させず位置表現でのみ本文に登場します。
   - 各ギャップに配置方式（統合 / 分離 / 再構成）判断 — このラベルも出力非露出。自然言語の位置・見出し表現でのみ本文に登場します。
   - 主要購買要素（KBF）1〜2 個とそれを裏付ける決定根拠（RTB）1〜2 個を分離 — このラベルも出力非露出。「その効益を裏付ける外部レビュー引用ボックス」のような自然言語でのみ本文に登場します。
8. **優先順位付与**: 自社ページの検索・AI 引用可能性に最も大きく影響する上位 3〜5 件のギャップを選別し、選別基準（AI 応答での露出頻度、ユーザー意図との直接関連性など）も併せて本文に一行明示します。
9. **改善提案 5 要素作成**: 各優先ギャップについて（追加位置 / コンテンツ形態 / 推奨見出し / 中核文または数値 / 期待効果）の 5 要素を一束として提示します。
10. **インサイト作成**: 自社コンテンツの構造的弱点 1 件と長期的に強化すべきコンテンツ戦略の方向性を整理します。
11. **自己点検**: 回答作成直前に自己点検チェックリストをすべて検証します。

# 3) 改善提案

[目標]
優先順位上位 3〜5 件のギャップについて、自社ページにどのように補強するかを（追加位置 / コンテンツ形態 / 推奨見出し / 中核文または数値 / 期待効果）の 5 要素で一束ずつ提示します。

## 分析ロジック

1. ギャップ診断要約で導出されたギャップのうち、自社ページの検索・AI 引用可能性に最も大きく影響する項目上位 3〜5 件を選別します。
2. 選別基準（AI 応答での露出頻度、ユーザー意図との直接関連性）も併せて本文に一行で明らかにします。
3. 各ギャップについて次の 5 要素を一束として作成します。
   - **追加位置**: 新規セクションの新設か、既存のどの段落を拡張するかを自然言語の位置表現で（例:「MX Vertical 製品詳細ページの主要機能セクション下部に新規段落」）。分析用語ラベル（PDP/Comparison/統合/分離/再構成）は出力しません。

   - **期待効果**: この補強が AI 応答露出とユーザー信頼にどのような影響を与え得るかを一行。

## 共通指示事項

- 約 400 文字内外で作成します。
- 分析用語ラベル（PDP / FAQ ページ種別 / Blog ページ種別 / Spec / Comparison ページ種別 / 統合 / 分離 / 再構成 / KBF / RTB）の出力本文への露出禁止。
