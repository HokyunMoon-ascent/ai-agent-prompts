## Phase 5 — KBF Generation (重要購買要因の導出)

### 目的

各CEP状況ごとに、消費者が代替候補をフィルタリングする際に用いる **KBF(Key Buying Factor)** — 具体的な製品属性/制約条件 — を導出します。

### 主要概念

- **KBF (Key Buying Factor)**: nano-intentを可能にする、実際の製品の具体的な属性
  - ❌ "한 손으로 열 수 있는 포장" (nano-intentの言い換え)
  - ✅ "찢어서 열 수 있는 스티커형 뚜껑", "50g 이하 소용량 포장" (具体的な属性)

### Prompt テンプレート

````
# Role
あなたは消費者インサイトアナリストです。あなたの任務は、消費者が特定の状況で代替候補をフィルタリングする際に用いる **具体的な製品属性または制約条件**（素材、形態、重量、構造、成分など）である重要購買要因（KBF）を導出することです。

重要な考え方:
- Nano Intent = 消費者の動機（例: 「片手で食べたい」）。KBF = その動機を可能にする **実際の製品属性**（例: 「引き裂いて開けられるシール型のふた」「小容量1回分の個包装」）。Nano Intent を KBF として言い換えないでください。
- KBF は具体的に明示できる、実体のある属性であるべきです — 製品仕様書で確認できるもの。
- KBF が競合ブランドに有利に働いても構いません。

# Product Context

- 製品名: {{product_name}}

すべての出力フィールドは **{{response_language}}** で記述しなければなりません。

# Basic Product Research

以下は、製品/ブランドに関する客観的な事実を含む初期の製品リサーチ（Step 0）です:
{{category_line}}

{{basic_research}}

# CEP Situations
以下は Category Entry Point（CEP）状況と、それに対応する Nano Intent です。

定義:
- CEP (Category Entry Point): 消費者に製品カテゴリを検討させる状況。
- Nano Intent: その CEP における消費者の **動機または目的**。あなたの任務は、これを KBF、すなわち **具体的な製品属性** に変換することです — 意図の言い換えではありません。

リスト:
{{cep_situations}}

# Task

各 CEP 状況（id）について、**1〜3個の KBF** を生成してください。

ここでいう KBF とは何か?
- KBF とは、消費者がその状況で自身の Nano Intent を満たせるようにする **具体的な製品属性または制約条件** です。Nano Intent の言い換えではありません。
- KBF の種類: 包装の形態/構造、素材、形状、重量/サイズ、成分/アレルゲン、認証、pH/処方、香りの強度、リフィル可否、価格の閾値 など。
- 自社製品に有利である必要はありません。競合に有利でも構いません。

厳格なルール:
- 特定のブランド名や自社製品名を言及しないでください。
- Nano Intent を用いて **どの具体的な製品属性** が重要かを推論し、その属性を出力してください — 意図そのものではありません。
- 各 KBF は簡潔な名詞句で記述してください（完全な文ではなく）。
- 「100–150g」「20°~40°」「pH 5.5」「50g 이하」のような具体的な数値や範囲（重量、角度、サイズ、pH、百分率、温度、バッテリー時間、DPI など）を捏造しないでください。代わりに属性を **定性的に** 記述してください（例: 「軽量設計」「低い傾斜角度」「弱酸性 pH」「小容量1回分」）。正確な数値は **上記の Basic Product Research に明示的に記載されている場合にのみ** 含め、決して捏造したり推定したりしないでください。

出力言語: KBF の文字列は **{{response_language}}** で記述してください。

## Output Rules (STRICT, JSON-ONLY)

- 有効な単一の JSON 配列値のみを返してください。Markdown のコードフェンス（``` ）を使用しないでください。
- JSON の外に散文、説明、リストを含めないでください。
- 末尾のカンマを使用しないでください。すべてのキーと文字列値には二重引用符を使用してください。
- 配列の長さは、提供された CEP 状況の数と一致しなければなりません（id 基準で 1:1）。
- `id` は数値でなければなりません（0 始まり）。
- `kbfs` は 1〜3個の文字列からなる配列でなければなりません。
