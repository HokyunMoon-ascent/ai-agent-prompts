## Phase 7-1 — ユーザープロンプト生成

### 目的

CEPごとに Nano Intent・KBF・カテゴリを入れて質問を1個生成（AI検索用の自然言語）

### 入力変数

| フィールド        | 型       | 必須                   | サーバーでの処理             |
| :---------------- | :------- | :--------------------- | :--------------------------- | --------- | ------------------------------------------------------------------------- |
| cepSituation      | string   | ✅                     | 空白除去、空の場合は 400     |
| nanoIntents       | string[] | デフォルト []          | 文字列のみ、trim、最大3個    |
| kbfs              | string[] | ✅（空はNG）           | 文字列のみ、trim、最大3個    |
| productCategories | string[] | デフォルト []          | 文字列のみ、trim             |
| country           | 'kr'     | 'jp'                   | 'us' など                    | デフォルト 'kr' | responseLocale がない場合の補助として使用                            |
| responseLocale    | 'ko'     | 'en'                   | 'ja'                         | 任意      | ある場合は lang 決定を優先（en/ja ならそのまま、なければ country で ja/en/ko） |

### リクエストモデルおよびパラメータ

| 項目      | 値                                                                                   |
| :-------- | :----------------------------------------------------------------------------------- |
| model     | 'gpt-5.4-nano'                                                                       |
| input     | buildCepUserPromptsPrompt(...) の結果である単一文字列（user メッセージに分離せず丸ごと input） |
| text      | { format: { type: 'text' } }                                                         |
| reasoning | { effort: 'none' }                                                                   |

---

### Prompt テンプレート

```
以下の CEP（Category Entry Point）状況、Nano Intent、KBF（Key Buying Factor）を使って、実際のユーザーが AI チャットボット（ChatGPT、Gemini、Perplexity など）に尋ねるような自然な質問を生成してください。

**重要なルール：**
1. 与えられた CEP 状況を自然に言い換えてください。
2. 以下に提供されるすべての KBF を自然に織り込んだ、包括的な質問をちょうど1つだけ生成してください。
3. 質問には CEP 状況の文脈を含め、すべての Key Buying Factor を自然で会話的な形で織り交ぜてください。
4. 製品カテゴリを自然に組み込んでください。
5. 技術的な製品仕様や正確な KBF 用語は使わないでください。代わりに、一般のユーザーが自然に使うような日常的な言葉で特徴を説明してください。
6. 正確な製品の特徴は知らないが、自分の状況で何が必要かは分かっている一般消費者の視点で書いてください。
7. 親切な友人と話すように、自然で会話的な言葉を使ってください。
8. 複数の購買要因が、バラバラなリストではなく、一つのまとまった質問の中で自然に流れるようにしてください。

**例：**
- CEP 状況: 出勤前に朝食を済ませなければならないとき
- Nano Intent: 「サクサク感を保つ」「素早く作る」「料理をルーティン化する」
- KBF 1: 「強化ガラスドア」
- KBF 2: 「クイック加熱技術」
- KBF 3: 「お手入れ簡単コーティング」

- 悪い例: 「仕事の後に夕食を済ませなければならないとき、強化ガラスドアとクイック加熱、お手入れ簡単なエアフライヤーを探しています。」
  -  ❌ CEP 状況を完全に変えてしまった。
  -  ❌ 技術的な製品仕様や正確な KBF 用語を使った。
  -  ❌ 自然な流れなしに特徴を並べた。

- 良い例: 「忙しい準備時間に、出勤前の朝食を済ませなければなりません。すぐに温まって手早く調理でき、中がよく見えて焼け具合をリアルタイムで確認でき、使った後はサッと拭き取れるエアフライヤーがほしいです。どんな製品がありますか？」
  - ✅ CEP 状況を含む（「出勤前の朝食を済ませる」）
  - ✅ Nano Intent を含む（「忙しい準備時間に」「手早く調理」）
  - ✅ すべての KBF の焦点を技術用語なしで自然に含む（「すぐに温まる」「中がよく見える」「サッと拭き取れる」）
  - ✅ 製品カテゴリを含む（「エアフライヤー」）
  - ✅ 複数のニーズが一つのまとまった質問の中で自然に流れる

質問は完全なストーリーを語る必要があります：ユーザーの状況（与えられた CEP）、達成したいこと（Nano Intent）、そして必要な製品の特徴（すべての KBF を自然に織り交ぜたもの）。
AI検索でよく現れる、意図の強い複合的なプロンプトに焦点を当ててください。
トーン：親切な同年代の人と話すように、くだけて親しみやすく、カジュアルで親近感のあるスタイルで書いてください。

Input:
- CEP Situation: ${cepSituation}
- Nano Intents:
${nanoIntentsText}
- KBFs (Key Buying Factors) - ALL must be included in the question:
${kbfsText}
- Product Categories: ${productCategoriesText}

Output language: ${langLabel}

Response format (output ONLY a JSON array with ONE question, nothing else):
["comprehensive question that includes all KBFs"]
```
