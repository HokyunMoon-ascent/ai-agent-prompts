## 1. 문서 개요

### 1.1 목적

본 문서는 `agent_aio_noneURL` 프롬프트가 정상 동작하기 위해 **개발팀이 채워주어야 할 5개 변수 슬롯**의 데이터 소스, 전처리 규칙, 데이터 형식, 에지 케이스를 정의합니다. 본 에이전트는 첫 슬롯의 URL 입력이 없을 때 갭 분석 대신 토글되어 노출되는 변형으로, 자사 페이지 콘텐츠 입력이 부재합니다.

### 1.2 대상 독자

- 백엔드 개발자 (데이터 파이프라인 구현)
- 프론트엔드 개발자 (분기 토글 UI 설계)
- 프롬프트 엔지니어 (프롬프트 입력값 검증)

## 2. 시스템 개요

### 2.1 Agent의 역할

자사 페이지 콘텐츠 비교 없이 AI 응답을 사용자 의도(CEP) 기반으로 진단·해설하는 응답 진단 에이전트. 사용자가 AI 응답을 깊이 이해하도록 돕는 동시에, 후속 온드미디어·언드미디어 전략 에이전트의 입력값을 생성합니다.

### 2.2 분기 위치

- **첫 번째 슬롯 토글**: URL 입력 없음 → 본 에이전트(`agent_aio_noneURL`) 노출 / URL 입력 있음 → 갭 분석 에이전트(`agent_aio_gap`) 노출
- **고정 노출**: 온드미디어 전략 에이전트, 언드미디어 전략 에이전트는 URL 유무와 무관하게 항상 동시 렌더링
- **선후행 의존성 없음**: 본 에이전트 결과를 다른 에이전트에 체이닝 입력으로 주지 않습니다(독립 동작)

### 2.3 입출력 요약

| 구분 | 항목 |
|---|---|
| **입력** | AI 검색 질문 / AI 응답 N개 / 대화 컨텍스트 |
| **출력** | 4섹션 마크다운 — 분석 개요(4 KPI 한 줄 진단 포함: Brand Visibility / Citation Visibility / Brand Sentiment / AI Traffic) / 브랜드 노출 분석(순위 위치·역할 컨텍스트) / 의미 영역 진단·해설(3계층 분해: 응답 프레임·브랜드 언급·근거 인용) / 후속 활용·핸드오프 메모 |
| **출력 포맷** | `:::accordion` 블록 + `**➊➋➌**` + `:k[..]` 키워드 표기 |

### 2.4 변수 슬롯 매핑 (전체 5개)

| 변수 슬롯 | 의미 | 데이터 소스 | 비고 |
|---|---|---|---|
| `{{user_prompt_B}}` | CEP 기반 AI 검색 질문 | 별도 워크플로우(노트북LM 참조) | 3.1 참조 |
| `{{ai_responses_C}}` | AI 응답 N개 | GPT에 B 질문 N회 반복 호출 | 3.2 참조 |
| `{{prev_q}}` | 직전 사용자 질문 | 채팅 세션 상태 | 3.3 참조 |
| `{{prev_a}}` | 직전 어시스턴트 답변 | 채팅 세션 상태 | 3.3 참조 |
| `{{user_question}}` | 현재 사용자 질문 | 채팅 입력 | 3.3 참조 |

> **갭 분석 대비 차이**: 갭 분석 에이전트(`agent_aio_gap`)의 `{{page_content_A}}`(자사 페이지 파싱 콘텐츠) 슬롯이 본 에이전트에는 존재하지 않습니다. URL 입력이 없으므로 자사 페이지 크롤링 단계 자체가 생략됩니다.

## 3. 변수별 상세 명세

### 3.1 `{{user_prompt_B}}` — AI 검색 질문 (CEP 기반)

#### 데이터 소스

- 별도 CEP 분석 워크플로우의 산출물 — 갭 분석과 동일 인터페이스 재사용
- 기존 `agent_ai_agent/GEO_prompt_builder` 결과물도 본 변수의 후보 (CEP별 10개 프롬프트 중 하나 선택)
- 워크플로우 정의는 NotebookLM 자료 참조 (갭 분석 dev_request 6.1 항 동일)

#### 입력 형태

- 단일 텍스트 단락 (한 사용자가 AI 검색에 던지는 자연어 질문)

#### 출력 형태 (변수에 주입될 형식)

- plain text 한 단락
- 길이: 50~300 단어 권장 (GEO_prompt_builder의 가이드 기준)
- **샘플 참조**: `src/B_AI에 던지는 질문 (CEP별로 만든 프롬프트).md`

#### 전처리 요구사항

- 별도 전처리 없음 (GEO_prompt_builder 출력을 그대로 주입)
- 직접 입력 모드를 추가로 지원할 경우 trim·줄바꿈 정리만 수행

#### 제약 / 에지 케이스

- 1회 분석 = 1개 B 질문 기준
- 다중 B를 동시 분석하는 경우 본 에이전트를 N번 호출하는 구조로 처리
- 빈 문자열 / 너무 짧은 질문(< 10단어)일 경우 입력 검증 단계에서 차단

---

### 3.2 `{{ai_responses_C}}` — AI 응답 N개

#### 데이터 소스

- **GPT(ChatGPT/GPT-4 계열)에 B 질문을 동일하게 N회 반복 호출**하여 응답 N개 수집 (권장 N=3)
- 동일 모델·다른 응답이므로 변동성(variance) 분석에 활용 — 본 에이전트의 차이 영역 진단의 직접 근거
- 호출 사양/모델 버전 등은 갭 분석 dev_request 3.3과 동일 정책

#### 입력 형태

- N회 LLM 호출 응답 텍스트 N개

#### 출력 형태 (변수에 주입될 형식)

- 단일 변수에 N개 응답을 합쳐서 주입
- **반드시 다음 구분자 형식을 따름** (프롬프트가 이 구분자로 응답을 식별):

```
### 1번 답변

(GPT 1회차 응답 본문)

### 2번 답변

(GPT 2회차 응답 본문)

### 3번 답변

(GPT 3회차 응답 본문)
```

- **샘플 참조**: `src/C_B프롬프트로 받은 AI 응답_1.md` ~ `_3.md` 3개 파일을 위 구분자 형식으로 합치면 동일한 결과

#### 전처리 요구사항

- 응답 본문에서 다음 잡음 영역 제거 권장:
  - 모델의 자기 소개 ("저는 ChatGPT입니다…")
  - 안전 가이드 메시지 ("의학적 조언은 전문가와…" 같은 반복적 면책 문구) — **단, 사용자에게 가치 있는 면책은 유지**
  - 인라인 광고/제휴 문구
- URL 인용은 보존 (브랜드 인용 패턴 분석에 필요)
- 줄바꿈은 원본 보존
- **브랜드 언급 위치 보존**: 응답 내 브랜드 등장 순서·문단 위치를 변경하지 않음(순위 위치 분석에 필수). 단락 재배치·정렬 금지

#### 호출 파라미터 권장값

| 파라미터 | 권장값 | 비고 |
|---|---|---|
| 모델 | GPT-4 계열 (예: gpt-4o, gpt-4-turbo) | 갭 분석과 동일 |
| temperature | 0.7~1.0 | 변동성 확보를 위해 결정성을 낮춤 |
| max_tokens | 2000 이상 | 샘플 응답 길이 기준 |
| 호출 간격 | 호출별 최소 1초 | 레이트리밋 안정성 |

#### 제약 / 에지 케이스

- 3회 중 1회 이상 실패 시 재시도 정책 필요 (최대 2회 재시도)
- 모든 호출 실패 시 사용자에게 에러 반환
- N=1, N=2도 지원 (프롬프트는 1개 입력 시 차이 영역 분석을 자동으로 비활성화)
- 응답 길이 폭증 시 (>5000 토큰) 잘라내지 말고 그대로 주입 — 프롬프트의 진단 톤이 보존되어야 함

#### 향후 확장 (현 버전 적용 안 함)

- 다양한 LLM(Claude / Perplexity / Gemini) 수평 비교 모드
- 노트북LM 검색 결과 직접 인입 모드

### 3.3 `{{prev_q}}`, `{{prev_a}}`, `{{user_question}}` — 대화 컨텍스트

#### 데이터 소스

- 채팅 세션 상태 관리 시스템 (기존 ai_agent 공통 패턴)
- 다른 ai_agent 프롬프트(`agent_aio_gap`, `agent_cluster`, `agent_persona_specialist` 등)와 동일한 변수 슬롯이므로 기존 인터페이스 재사용 가능

#### 입력 형태

- `{{prev_q}}`, `{{prev_a}}`: 직전 턴의 텍스트
- `{{user_question}}`: 현재 사용자 입력

#### 출력 형태

- 단일 텍스트 (마크다운 가능)

#### 제약 / 에지 케이스

- 첫 턴 호출 시 `{{prev_q}}`, `{{prev_a}}`는 빈 문자열로 채움 (프롬프트가 빈 값 처리를 가정하고 있음)
- 멀티턴 대화에서 N-2턴 이전 컨텍스트는 보존하지 않음 (현재 1턴 슬라이딩 윈도우)

## 4. 데이터 흐름도

```
[사용자 입력]
   ├─ AI 검색 질문 텍스트(또는 GEO_prompt_builder ID) ──┐
   └─ 사용자 질문 ────────────────────┐                 │
                                       │                 │
                                       ▼                 ▼
[전처리 파이프라인]                     │                 │
   ├─ B 텍스트 정리 ─────→ {{user_prompt_B}}
   └─ GPT N회 호출 ──────→ {{ai_responses_C}}
                                       │
                                       ▼
[프롬프트 조립]
   v.0.1.0_aio_noneURL_KR_0504.md + 5개 변수
                                       │
                                       ▼
[LLM 호출]
   Claude / GPT 등 (본 에이전트 실행 모델)
                                       │
                                       ▼
[출력]
   4섹션 마크다운 (분석 개요 / 브랜드 노출 / 의미 영역 진단·해설 / 후속 활용·핸드오프 메모)
                                       │
                                       ▼
[후속 처리]
   - 사용자에게 즉시 표시
```

## 5. 검증 기준

### 5.1 기능 검증

| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 (N=3) | B + C 3개 | 4섹션 모두 출력, 공통 영역 / 차이 영역 분리, 핸드오프 라벨 N개 표기 |
| C가 1개만 입력 | B + C 1개 | 차이 영역 진단에 "단일 응답 입력으로 차이 분석은 적용되지 않음" 명시 |
| AI 검색 질문이 빈 값 | B=빈 문자열 | 입력 검증 단계에서 차단 (서버 측) |
| GPT 호출 부분 실패 | N=3 중 1회 실패 → 2회 재시도 후 2개로 진행 | 프롬프트는 N=2로 정상 동작해야 함 |
| URL 입력 토글 충돌 | 사용자가 분석 도중 URL 추가 입력 | 본 에이전트 언마운트 후 갭 분석 에이전트 마운트 (UI 측 책임) |

### 5.2 출력 품질 검증 (프롬프트 자체 점검 체크리스트와 매칭)

1. 진단 only: "자사 페이지에 부재" 같은 갭 추론 표현이 출력에 섞이지 않음
2. 출처 강제: 모든 `:k[..]`가 AI 응답/AI 검색 질문 원문에 실재
3. 직접 수정 문구 금지: "넣으세요/교체하세요/이렇게 쓰세요" 미출력
4. 사용자 의도 정합성: 모든 의미 영역 진단에 CEP/KBF/RTB 정합성 1문장 포함
5. 응답 그룹핑: 공통 영역 / 차이 영역 분리 적용 (응답 1개면 차이 미적용 명시)
6. 후속 소비 가능성: 엔티티 분해 / 토픽 분해 분리 명시
7. 핸드오프 라벨: 섹션 4에 온드 미디어 입력 후보 / 언드 미디어 입력 후보 라벨 리스트 명시
8. 용어 표기 규칙: B/C·C1/C2/C3·consensus/variance 같은 내부 라벨이 출력에 노출되지 않음
9. 3계층 분해: 모든 의미 영역 진단에 응답 프레임·브랜드 언급·근거 인용 3계층이 분리 표기됨
10. 4 KPI 한 줄 진단: 분석 개요에 Brand Visibility / Citation Visibility / Brand Sentiment / AI Traffic 4축이 모두 명시됨
11. 순위·역할 컨텍스트: 브랜드 인용 패턴에 각 브랜드의 순위 위치(1순위/대안/단순 언급)와 역할 컨텍스트(대표 해답/대안/비교/부정)가 명시됨

### 5.3 성능 / SLA

| 지표 | 목표 |
|---|---|
| GPT N회 호출 (병렬) | < 30초 |
| 본 에이전트 LLM 호출 | < 60초 (출력 길이 기준) |
| End-to-End | < 90초 (URL 크롤링 단계 부재로 갭 분석 대비 약 30초 단축) |
