## 2. 시스템 개요

### 2.1 Agent의 역할

자사 페이지(A)와 사용자 의도 기반 AI 응답(C)을 비교하여 자사 페이지에 결손된 의미적 영역만 도출하는 콘텐츠 갭 분석 에이전트. 출력은 후속 콘텐츠 작성 에이전트(온드/언드/샘플)의 입력으로 소비됩니다.

### 2.2 입출력 요약

| 구분 | 항목 |
|---|---|
| **입력** | 자사 페이지 콘텐츠 / AI 검색 질문 / AI 응답 N개 / 대화 컨텍스트 |
| **출력** | 4섹션 마크다운 — 분석 개요 / 브랜드 노출 분석(Brand Mention × Content Citation 2축 매트릭스 포함) / 의미적 갭 매핑(엔티티 갭 5분류 + 원인 신호 4축 라벨링) / 보강 권장사항 |
| **출력 포맷** | `:::accordion` 블록 + `**➊➋➌**` + `:k[..]` 키워드 표기 |

### 2.3 변수 슬롯 매핑 (전체 6개)

| 변수 슬롯 | 의미 | 데이터 소스 | 비고 |
|---|---|---|---|
| `{{page_content_A}}` | 자사 페이지 파싱 콘텐츠 | 사용자 입력 URL 크롤링 | 3.1 참조 |
| `{{user_prompt_B}}` | CEP 기반 AI 검색 질문 | 별도 워크플로우(노트북LM 참조) | 3.2 참조 |
| `{{ai_responses_C}}` | AI 응답 N개 | GPT에 B 질문 3회 반복 호출 | 3.3 참조 |
| `{{prev_q}}` | 직전 사용자 질문 | 채팅 세션 상태 | 3.4 참조 |
| `{{prev_a}}` | 직전 어시스턴트 답변 | 채팅 세션 상태 | 3.4 참조 |
| `{{user_question}}` | 현재 사용자 질문 | 채팅 입력 | 3.4 참조 |

## 3. 변수별 상세 명세

### 3.1 `{{page_content_A}}` — 자사 페이지 파싱 콘텐츠

#### 데이터 소스

- 사용자가 입력한 자사 페이지 URL을 크롤링하여 본문 텍스트만 추출
- **크롤링 사양은 NotebookLM 자료를 참조** (description.md 명시 노트북: <https://notebooklm.google.com/notebook/b5ad73ea-0078-413a-9a2e-612ed5da3621>)

#### 입력 형태

- 단일 페이지 URL 또는 라인업 페이지 N개 URL
- 라인업 N개일 경우 단일 변수에 합쳐서 전달 (현재 샘플: MX Vertical / Lift / MX ERGO 3개 페이지가 합쳐진 형태)

#### 출력 형태 (변수에 주입될 형식)

- 마크다운 또는 plain text
- 메뉴/CTA/푸터 같은 비콘텐츠 영역은 가능한 한 제거 (Readability 알고리즘 등)
- 제품 영역 사이에 명확한 구분자(예: `---` 또는 `## 제품명`) 권장
- **샘플 참조**: `src/A_가이드에 사용하는 내 페이지를 파싱한 콘텐츠 .md`

#### 전처리 요구사항

- HTML → 텍스트 변환
- 메인 콘텐츠 추출 (Readability/Trafilatura 또는 동등 알고리즘)
- 제품별 영역 구분자 삽입
- 인코딩: UTF-8

#### 제약 / 에지 케이스

- 토큰 한계: 프롬프트 본문 + A + B + C ≤ 모델 컨텍스트 윈도우 (Claude Opus 200k 기준 안전권은 100k 이하 권장)
- 페이지 크기 초과 시 청킹 또는 요약 사전처리 필요 (요약 시 의미 일치 원칙이 흐려지므로 권장하지 않음)
- 크롤링 실패 시: 에러 메시지를 명확히 반환하고 사용자에게 직접 텍스트 입력 옵션 제공

#### 미지원 사례

- 로그인 필요 페이지, JavaScript 렌더링 의존 페이지: 별도 헤드리스 브라우저 처리 필요 — NotebookLM 자료 참조

### 3.2 `{{user_prompt_B}}` — AI 검색 질문 (CEP 기반)

#### 데이터 소스

- 별도 CEP 분석 워크플로우의 산출물
- **워크플로우 정의는 NotebookLM 자료를 참조** (description.md 명시 노트북: <https://notebooklm.google.com/notebook/2643c969-0f4f-4b67-886d-4630fdfdf6ed>)
- 기존 `agent_ai_agent/GEO_prompt_builder` 결과물도 본 변수의 후보 (CEP별 10개 프롬프트 중 하나 선택)

#### 입력 형태

- 단일 텍스트 단락 (한 사용자가 AI 검색에 던지는 자연어 질문)

#### 출력 형태 (변수에 주입될 형식)

- plain text 한 단락
- 길이: 50~300 단어 권장 (GEO_prompt_builder의 가이드 기준)
- **샘플 참조**: `src/B_AI에 던지는 질문 (CEP별로 만든 프롬프트).md`

#### 전처리 요구사항

- 별도 전처리 없음 (GEO_prompt_builder 출력을 그대로 주입)
- 직접 입력 모드를 추가로 지원할 경우 trim·줄바꿈 정리만 수행

#### 제약 / 에지 케이스

- 1회 분석 = 1개 B 질문 기준
- 다중 B를 동시 분석하는 경우 본 에이전트를 N번 호출하는 구조로 처리
- 빈 문자열 / 너무 짧은 질문(< 10단어)일 경우 입력 검증 단계에서 차단

---

### 3.3 `{{ai_responses_C}}` — AI 응답 N개

#### 데이터 소스

- **GPT(ChatGPT/GPT-4 계열)에 B 질문을 동일하게 3회 반복 호출**하여 응답 3개 수집
- 동일 모델·다른 응답이므로 변동성(variance) 분석에 활용
- **호출 사양/모델 버전 등은 NotebookLM 자료를 참조**

#### 입력 형태

- 3회 LLM 호출 응답 텍스트 3개

#### 출력 형태 (변수에 주입될 형식)

- 단일 변수에 3개 응답을 합쳐서 주입
- **반드시 다음 구분자 형식을 따름** (프롬프트가 이 구분자로 응답을 식별):

```
### 1번 답변

(GPT 1회차 응답 본문)

### 2번 답변

(GPT 2회차 응답 본문)

### 3번 답변

(GPT 3회차 응답 본문)
```

- **샘플 참조**: `src/C_B프롬프트로 받은 AI 응답_1.md` ~ `_3.md` 3개 파일을 위 구분자 형식으로 합치면 동일한 결과

#### 전처리 요구사항

- 응답 본문에서 다음 잡음 영역 제거 권장:
  - 모델의 자기 소개 ("저는 ChatGPT입니다…")
  - 안전 가이드 메시지 ("의학적 조언은 전문가와…" 같은 반복적 면책 문구) — **단, 사용자에게 가치 있는 면책은 유지**
  - 인라인 광고/제휴 문구
- URL 인용은 보존 (RTB 분석에 필요)
- 줄바꿈은 원본 보존

#### 호출 파라미터 권장값

| 파라미터 | 권장값 | 비고 |
|---|---|---|
| 모델 | GPT-4 계열 (예: gpt-4o, gpt-4-turbo) | NotebookLM 자료 확인 후 확정 |
| temperature | 0.7~1.0 | 변동성 확보를 위해 결정성을 낮춤 |
| max_tokens | 2000 이상 | 샘플 응답 길이 기준 |
| 호출 간격 | 호출별 최소 1초 | 레이트리밋 안정성 |

#### 제약 / 에지 케이스

- 3회 중 1회 이상 실패 시 재시도 정책 필요 (최대 2회 재시도)
- 모든 호출 실패 시 사용자에게 에러 반환
- N=1, N=2도 지원 (프롬프트는 1개 입력 시 차이 영역 분석을 자동으로 비활성화)
- 응답 길이 폭증 시 (>5000 토큰) 잘라내지 말고 그대로 주입 — 프롬프트의 "의미 일치 원칙"이 보존되어야 함

#### 향후 확장 (현 버전 적용 안 함)

- 다양한 LLM(Claude / Perplexity / Gemini) 수평 비교 모드
- 노트북LM 검색 결과 직접 인입 모드

### 3.4 `{{prev_q}}`, `{{prev_a}}`, `{{user_question}}` — 대화 컨텍스트

#### 데이터 소스

- 채팅 세션 상태 관리 시스템 (기존 ai_agent 공통 패턴)
- 다른 ai_agent 프롬프트(`agent_cluster`, `agent_persona_specialist` 등)와 동일한 변수 슬롯이므로 기존 인터페이스 재사용 가능

#### 입력 형태

- `{{prev_q}}`, `{{prev_a}}`: 직전 턴의 텍스트
- `{{user_question}}`: 현재 사용자 입력

#### 출력 형태

- 단일 텍스트 (마크다운 가능)

#### 제약 / 에지 케이스

- 첫 턴 호출 시 `{{prev_q}}`, `{{prev_a}}`는 빈 문자열로 채움 (프롬프트가 빈 값 처리를 가정하고 있음)
- 멀티턴 대화에서 N-2턴 이전 컨텍스트는 보존하지 않음 (현재 1턴 슬라이딩 윈도우)

## 5. 검증 기준

### 5.1 기능 검증

| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 | A·B·C 모두 정상 | 4개 섹션 모두 출력, 공통 갭/차이 갭 분리 |
| C가 1개만 입력 | A·B·C(1개) | 차이 영역 섹션에 "단일 응답 입력으로 차이 분석은 적용되지 않음" 명시 |
| 자사 페이지가 빈 값 | A=빈 문자열 | 입력 검증 단계에서 차단 (서버 측) |
| 크롤링 실패 | URL 응답 없음 | 사용자에게 에러 + 직접 입력 옵션 제공 |
| GPT 호출 부분 실패 | 3회 중 1회 실패 → 2회 재시도 후 2개로 진행 | 프롬프트는 N=2로 정상 동작해야 함 |

### 5.2 출력 품질 검증 (프롬프트 자체 점검 체크리스트와 매칭)

1. 누락 only 원칙: 자사 페이지에 이미 있는 항목이 갭 매핑에 섞이지 않음
2. 의미 일치 원칙: 표현 차이만으로 갭 분류된 항목 없음
3. 직접 수정 문구 금지: "넣으세요/교체하세요/이렇게 쓰세요" 미출력
4. 출처 강제: 모든 `:k[..]`가 자사 페이지/AI 응답 원문에 실재
5. 통합/분리 판단: 모든 보강 권장에 라벨 + 1문장 근거
6. 후속 소비 가능성: 엔티티 후보/토픽 후보 분리 명시
7. 응답 그룹핑: 공통 영역/차이 영역 분리 적용
8. 용어 표기 규칙: A/B/C·C1/C2/C3·consensus/variance 같은 내부 라벨이 출력에 노출되지 않음
9. 엔티티 갭 5분류: 모든 갭에 카테고리/속성/CEP/관계/신뢰 중 1개 이상 분류 라벨 부여
10. 원인 신호 4축: 모든 갭에 관련성/신뢰성/다양성/최신성 중 부족 축이 1개 이상 표기
11. Brand × Citation 매트릭스: 브랜드 노출 분석에 4사분면(언급×인용)과 사분면별 의미 해석 명시

### 5.3 성능 / SLA

| 지표 | 목표 |
|---|---|
| 크롤링 응답 시간 | < 10초 (단일 페이지) |
| GPT 3회 호출 (병렬) | < 30초 |
| 본 에이전트 LLM 호출 | < 60초 (출력 길이 기준) |
| End-to-End | < 120초 |

> 출력 길이 가이드: 평균 약 7,487 bytes(±2,000 bytes 권장), 허용 범위 1,630~12,330 bytes. 길이를 늘리기 위해 외부 사실/추측을 끌어오지 않습니다(출처 강제 원칙 우선).
