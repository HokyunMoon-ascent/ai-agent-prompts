신설 — Phase 3.5 증거 분해

웹서치 산문을 quote(verbatim)+url 단위로 분해해 w7 부분필드 · nano_intent 후보 · KBF 힌트 · RTB · source_ref를 추출합니다. quote가 뒷받침하지 않는 필드는 비워두는 것이 정답(억지 채움 금지). 초안: phase3-5_ Evidence Decomposition (증거 분해)/KR/v.1.0.0_…_0710.md

Phase 4 — 생성에서 조립로

입력이 산문에서 증거 유닛 JSON으로 교체됩니다. 같은 source_ref 유닛 1–3개를 선택·결합해 장면을 쓰되, 모든 구체어(시간·장소·발화·행동)는 유닛 quote에 대응해야 합니다. 섹션 간 결합 금지(맥락 합성 방지). 초안: phase4_…/KR/v.1.1.0_…_0710.md

Phase 5 — 힌트 대조로 확정

P4가 넘긴 kbf_hints를 basic research와 대조해 KBF를 확정하는 역할로 좁아집니다. 기존 숫자 날조 금지 규칙은 유지. 파일 개정은 후속 작업으로 남깁니다.

검증 — 사후 교정 → 회귀 감시

지금은 검증기가 걸러낸 카드를 사람이 repropose로 사후 교정합니다(1328: 10장 중 6장). To-Be에서는 접지가 생성 시점에 끝나므로, 검증은 회귀 감시로 이동 — fail/warning이 나오면 카드가 아니라 P3.5·P4 프롬프트를 고칩니다.

근거 — project 1328에서 확인된 4대 환각 유형

Hallucination_test 검증에서 fail/warning 사유는 전부 아래 네 패턴이었고, P3.5의 금지 규칙은 이 유형들과 1:1로 대응합니다.

왜 이렇게 설계했나 — 쉬운 해설

설계 판단의 근거를 Q&A로 풀었습니다.

Q.왜 Phase 3 자체를 고치지 않고 별도 단계를 만드나요?

Phase 3은 web_search가 켜진 산문 생성이라 구조화 JSON을 강제하면 리서치 품질(자연스러운 탐색)이 떨어집니다. 분해는 tools 없는 값싼 후처리 호출로 분리하는 편이 안전하고, Phase 3 프롬프트는 무수정으로 유지됩니다.

Q.왜 Phase 4가 분해까지 흡수하면 안 되나요?

"인용을 뽑는 판단"과 "장면을 만드는 생성"을 한 호출에 섞으면, 모델이 장면을 먼저 정하고 인용을 거기에 끼워 맞추는 환각이 재발합니다. 1328의 warning들이 정확히 이 패턴이었습니다. 분해(P3.5)가 먼저 재료를 고정하고, 조립(P4)은 재료 밖으로 못 나가게 하는 게 핵심입니다.

Q.비용은 얼마나 늘어나나요?

프로젝트당 호출 +1. P3.5는 P4와 같은 계열(gpt-5.4-nano · tools 없음 · reasoning none)이라 웹서치 단계 대비 저렴합니다. 대신 사후 repropose에 들던 수작업 교정(1328 기준 카드의 60%)이 사라집니다.

Q.w7 필드를 억지로 다 채우면 안 되나요?

안 됩니다. 빈 필드를 채우는 순간이 곧 환각입니다. "quote가 뒷받침하는 필드만"이 원칙이고, 얇은 카드는 다양성 quota가 다른 섹션에서 보충합니다. 희소하지만 접지된 카드가, 풍부하지만 지어낸 카드보다 낫습니다.

Q.RTB와 source_ref는 뒤 단계에서 뭘 좋게 하나요?

카드가 재인용 가능한 근거를 갖고 다니므로, P6(MA 진단)의 브랜드 인식 점검과 P8(콘텐츠 가이드)의 "신뢰 근거 배치"가 추가 조사 없이 가능해집니다. 브랜드 입장에서 AI 추천 후보군에 들어가려면 장면마다 RTB가 필요하다는 결론(1328 summary)과 직결됩니다.

Q.brand_nonBrand To-Be 맵과는 어떤 관계인가요?

독립적인 제안입니다. 이 문서는 현행 파이프라인 대비 grounding 변경만 다루며, 게이트 제안(cep_pipeline_asis_tobe_map.html)과 충돌 없이 합성 가능합니다 — 게이트는 파이프라인 앞, P3.5는 중간이라 서로 다른 구간을 바꿉니다.
