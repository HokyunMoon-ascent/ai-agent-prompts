## 1. 문서 개요

### 1.1 목적

본 문서는 `agent_aio_earned` 프롬프트가 정상 동작하기 위해 **개발팀이 채워주어야 할 5개 변수 슬롯**의 데이터 소스, 전처리 규칙, 데이터 형식, 에지 케이스를 정의합니다. 본 에이전트는 자사 매체가 아닌 외부 커뮤니티·소셜 채널 영역의 RTB(Reason to Believe) 활성화 가이드를 채널 단위로 제안합니다.

### 1.2 대상 독자

- 백엔드 개발자 (데이터 파이프라인 구현)
- 프론트엔드 개발자 (입력 UI 설계)
- 프롬프트 엔지니어 (프롬프트 입력값 검증)

### 1.3 관련 산출물

- **프롬프트 파일**: `agents/ai_agent/agent_aio_earned/KR/v.0.2.0_aio_earned_KR_0504.md` (현행) / `KR/v.0.1.0_aio_earned_KR_0504.md` (이전 버전)
- **요구사항 원문**: `agents/ai_agent/agent_aio_earned/src/description.md`
- **선행 에이전트**: `agents/ai_agent/agent_aio_gap/KR/v.0.1.0_aio_gap_KR_0430.md` (출력의 ③·④ 섹션이 본 에이전트의 1차 입력)

## 2. 시스템 개요

### 2.1 Agent의 역할

자사 페이지(A)와 사용자 의도 기반 AI 응답(C)을 비교한 갭 분석 결과 중, **외부 매체에서 형성되어야 하는 RTB 신호**를 식별하고 채널 단위 활성화 가이드를 산출하는 에이전트. 4단계 콘텐츠 가이드 파이프라인(① Findings → ② Owned → ③ Earned → ④ Action Items) 중 ③ 위치를 담당하며, 출력은 ④ Action Items 및 후속 샘플 작성 에이전트로 전달됩니다. 본 에이전트는 정직한 신호 형성에 한정되며, 비윤리 바이럴(유저 사칭·매수 후기·계정 도배·경쟁사 비방·언론 사칭)을 명시적으로 배제합니다.

### 2.2 입출력 요약

| 구분 | 항목 |
|---|---|
| **입력** | AI 응답 N개 / AI 검색 질문 / 갭 분석 결과 / 대화 컨텍스트 |
| **출력** | 4섹션 마크다운 — 인용 외부 매체 추출 / 매체별 RTB 갭 매핑(방향성 일치도 포함) / 채널별 활성화 전략(채널 역할 분리: 실사용 경험 / 생활 언어 / 제3자 검증 + 권장 표현 패턴) / 윤리 가드레일 자체 점검 |
| **출력 포맷** | `:::accordion` 블록 + `**➊➋➌➍➎**` + `:k[..]` 키워드 표기 |

### 2.3 변수 슬롯 매핑 (전체 5개)

| 변수 슬롯 | 의미 | 데이터 소스 | 비고 |
|---|---|---|---|
| `{{ai_responses_C}}` | AI 응답 N개 (외부 매체 인용 추출 대상) | `agent_aio_gap` 입력 재사용 | 3.1 참조 |
| `{{user_prompt_B}}` | CEP 기반 AI 검색 질문 (RTB 단서 컨텍스트) | `agent_aio_gap` 입력 재사용 | 3.2 참조 |
| `{{gap_findings}}` | 선행 갭 분석 에이전트 출력의 ③·④ 섹션 발췌 | `agent_aio_gap` 출력 후처리 | 3.3 참조 |
| `{{prev_q}}`, `{{prev_a}}`, `{{user_question}}` | 대화 컨텍스트 (1턴 슬라이딩) | 채팅 세션 상태 | 3.4 참조 |

## 3. 변수별 상세 명세

### 3.1 `{{ai_responses_C}}` — AI 응답 N개

#### 데이터 소스

- `agent_aio_gap`에서 사용한 동일한 AI 응답 N개를 그대로 재사용합니다(파이프라인상 동일 사용자 의도 기준선이므로 재크롤링 불필요).
- 단독 호출 시 GPT(ChatGPT/GPT-4 계열)에 사용자 질문을 동일하게 3회 반복 호출하여 응답 3개를 수집합니다(상세 사양은 `agent_aio_gap` dev_request 3.3 참조).

#### 입력 형태 / 출력 형태

- 단일 변수에 N개 응답을 합쳐서 주입하며, **반드시 다음 구분자 형식을 따름**:

```
### 1번 답변

(GPT 1회차 응답 본문)

### 2번 답변

(GPT 2회차 응답 본문)

### 3번 답변

(GPT 3회차 응답 본문)
```

- **샘플 참조**: `agents/ai_agent/agent_aio_gap/src/C_B프롬프트로 받은 AI 응답_1.md` ~ `_3.md`

#### 전처리 요구사항

- 매체명·URL·도메인 표기는 **반드시 보존**합니다(본 에이전트의 외부 매체 추출 대상이므로 어떠한 정제·익명화도 금지).
- 모델 자기 소개·반복 면책 문구·인라인 광고는 제거 권장 (`agent_aio_gap` 동일 정책).
- 줄바꿈은 원본 보존.

#### 제약 / 에지 케이스

- N=1, N=2도 지원 (프롬프트는 1개 입력 시 차이 갭 분석을 자동 비활성화).
- 외부 매체 인용이 0개인 경우(AI가 자사·일반 지식만으로 답변): 인용 외부 매체 추출 섹션의 5개 카테고리 모두 "해당 응답에서 인용 없음" 명시 + 매체별 RTB 갭 매핑은 "활성화 대상 없음"으로 표기.

### 3.2 `{{user_prompt_B}}` — AI 검색 질문 (CEP 기반)

#### 데이터 소스

- `agent_aio_gap`과 동일한 CEP 기반 AI 검색 질문을 그대로 재사용합니다.
- 본 에이전트에서는 RTB 단서(질문에 담긴 사용자가 결정 근거로 기대하는 정보 유형) 추출 컨텍스트로 사용됩니다.

#### 입력 형태 / 출력 형태

- 단일 텍스트 단락 (한 사용자가 AI 검색에 던지는 자연어 질문)
- 길이: 50~300 단어 권장
- **샘플 참조**: `agents/ai_agent/agent_aio_gap/src/B_AI에 던지는 질문 (CEP별로 만든 프롬프트).md`

#### 전처리 요구사항 / 제약

- `agent_aio_gap` dev_request 3.2와 동일.

### 3.3 `{{gap_findings}}` — 갭 분석 결과 발췌

#### 데이터 소스

- `agent_aio_gap`의 출력 마크다운에서 다음 두 영역을 발췌해 단일 변수에 주입합니다.
  - **③ 의미적 갭 매핑** (전체)
  - **④ 보강 권장사항** 중 **채널 힌트가 언드(또는 언드+샘플)** 인 항목만 필터

#### 입력 형태 / 출력 형태 (변수에 주입될 형식)

- 마크다운 그대로 주입 (`agent_aio_gap` 출력 양식 보존)
- 발췌 시 다음 구분자 형식 권장:

```
## 의미적 갭 매핑 (선행 분석 결과)

(agent_aio_gap 출력의 3) 섹션 본문 그대로)

## 보강 권장사항 — 언드 채널 항목 (선행 분석 결과)

(agent_aio_gap 출력의 4) 섹션에서 채널 힌트=언드 또는 언드+샘플 인 항목만 추출)
```

#### 전처리 요구사항

- `agent_aio_gap` 출력에서 ④ 섹션 항목별로 `채널 힌트:` 라인을 정규식 또는 마크다운 파싱으로 검사하고, **언드** 또는 **언드+샘플** 키워드를 포함하는 항목만 보존합니다.
- ③ 섹션은 RTB 단서 추출 모수이므로 필터 없이 그대로 보존합니다.
- 내부 라벨(`A`, `B`, `C`, `consensus`, `variance`)이 갭 출력에 노출되지 않도록 `agent_aio_gap`이 이미 보장하므로, 본 단계에서는 추가 라벨 정제 불필요(다만 회귀 점검에서 grep 권장).
- **추상 평가어 정제**: 갭 분석 결과 본문에 추상 평가어("최고", "좋아요", "추천" 단독)가 포함되어 있다면 RTB 단서로 사용하지 않도록 사전 필터 권장(본 에이전트는 속성·맥락 동반 표현만 권장 표현 패턴으로 산출하므로 입력 단계에서 정제하면 출력 품질 향상).

#### 제약 / 에지 케이스

- ④ 섹션에서 언드 라벨 항목이 0개일 수 있음 → 본 에이전트는 매체별 RTB 갭 매핑·채널 전략을 "활성화 대상 없음"으로 표기하고, 인용 외부 매체 추출과 윤리 가드레일 자체 점검은 정상 출력합니다.
- ③ 섹션이 비어 있는 경우(갭이 도출되지 않음): 본 에이전트 호출이 의미가 없으므로 **호출 단계에서 차단**하고, "선행 갭 분석에서 갭이 도출되지 않음 — 언드 활성화 대상 없음" 메시지를 사용자에게 직접 반환하는 정책 권장.

## 5. 검증 기준

### 5.1 기능 검증

| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 | C 3개·B·gap_findings 정상 | 4개 섹션 모두 출력, 5 카테고리 매체 분류, 채널 전략에 인증·투명성 요건 명시 |
| C가 1개만 입력 | C(1개) | 매체별 RTB 갭 매핑이 공통 갭만 사용 + "단일 응답 입력으로 차이 갭 분석은 적용되지 않음" 명시 |
| 외부 매체 인용 0개 | C 3개에 매체 인용 없음 | 인용 매체 추출의 5 카테고리 모두 "해당 응답에서 인용 없음" 명시, 매체별 RTB·채널 전략은 "활성화 대상 없음" |
| gap_findings 언드 항목 0개 | gap 출력에서 ④ 언드 라벨 없음 | 분석 개요에 "선행 갭 분석에서 언드 채널 활성화 항목이 도출되지 않음" 명시 + 매체별 RTB·채널 전략은 "활성화 대상 없음" |
| gap_findings 자체가 빈 값 | ③ 섹션도 비어 있음 | 호출 차단 (서버 측), 사용자에게 "갭 도출 없음" 안내 |
| 윤리 가드 위반 시도 | 프롬프트에 "유저인 척 작성" 요청 인입 | 본 에이전트는 출력에서 배제하고, 윤리 가드레일 자체 점검 ➌ 잔여 리스크 노트에 위반 시도 인입 사실 1줄 명시 |

### 5.2 출력 품질 검증 (프롬프트 자체 점검 체크리스트와 매칭)

1. 윤리 가드레일: 위장·미공시·도배·사칭·비방 제안이 어떤 표현으로도 출력에 섞이지 않음 (**최우선**)
2. 인증·투명성: 모든 채널 전략에 협찬 표시·공식 계정 식별·이해관계 공시 등 인증 요건 명시
3. 출처 강제: 모든 `:k[..]`가 AI 응답/갭 분석 결과 원문에 실재
4. 누락 only 원칙: 자사 페이지가 이미 다루는 영역이 매체 가이드에 섞이지 않음
5. 직접 수정 문구 금지: "올리세요/작성하세요/이렇게 쓰세요" 미출력
6. 후속 소비 가능성: 채널 단위로 엔티티 후보·토픽 후보·증거 형식 분리 명시
7. 응답 그룹핑: 공통 갭/차이 갭 분리 적용
8. 용어 표기 규칙: A·B·C·C1/C2/C3·findings·consensus·variance 같은 내부 라벨 미노출
9. 채널 역할 분리: 모든 Section 3 채널 항목에 실사용 경험 / 생활 언어 / 제3자 검증 중 1개가 채널 역할로 명시
10. 경험 언어 가이드: 모든 권장 표현 패턴이 추상 평가어 단독("최고", "좋아요" 등)이 아니라 속성·맥락 동반 문장 형태
11. 방향성 일치도: Section 2 매핑 항목에 1순위·보조 매체의 방향성 일치도가 1문장으로 표기됨
