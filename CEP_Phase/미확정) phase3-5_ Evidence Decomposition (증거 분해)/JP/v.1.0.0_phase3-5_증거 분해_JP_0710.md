## Phase 3.5 — Evidence Decomposition (証拠分解)

### 目的

Phase 3(CEP Insight Research)・Phase 3-1(Latent Intent)のウェブサーチ散文から **verbatim 引用を構造化された「証拠ユニット(evidence unit)」へ分解**します。
以降の工程(Phase 4 CEP 組み立て、Phase 5 KBF 確定)は、このユニット **外の表現を新たに作れないようにする** ことで、ソースに存在しない具体化(ハルシネーション)を生成段階で遮断する grounding 工程です。

> 背景: Hallucination_test 検証(例: project 1328)において、fail/warning カードの原因はすべて
> 「散文リサーチ → カード直行」の過程で生じた **ソースに存在しない具体化** であった。
> 事後 repropose で行っていた「検証済み引用のみで w7・nano_intent・KBF・RTB へ分解 + source_ref 明示」を
> パイプラインの正式な工程へ移したものが本 Phase。

### コアコンセプト

- **証拠ユニット (Evidence Unit)**: 本文から verbatim で抜粋した quote 1 個を中心に、その quote が直接裏付ける w7 部分フィールド・ナノインテント候補・KBF ヒント・RTB・source_ref をまとめた最小の根拠単位
- **verbatim**: 本文の文をそのまま(文字どおり)コピーしたもの。意訳・要約・合成は禁止
- **RTB (Reason To Believe)**: 消費者/読者に再引用可能な形へ整えた quote(内容の追加なし、トリミングのみ許可)
- **source_ref**: quote が属する本文セクション番号(`§N` 表記)
- **4 大ハルシネーション類型**(検証で繰り返し確認されたパターン — 本工程で明示的に禁止):
  1. **時間の断定** — ソースにない期間/時点の特定(例: 「첫 주」「주말」)
  2. **存在しない場所** — ソースにない場所の追加(例: 「도서관」)
  3. **偽の引用** — 意訳を引用符で囲み、実在の発話のように表記
  4. **存在しない行動** — ソースにない行動の記述(例: 「다시 검색」)

### 出力形式

JSON 配列(証拠ユニットのリスト — 個数制限なし、本文が裏付ける分だけ)

```json
[
  {
    "unit_id": 1,
    "source_ref": "§1",
    "quote": "소파나 침대 옆에 노트북을 두고(팔이 자연스럽게 내려가지 않는 자세로) 업무를 보다 보니, 손목이 몸쪽으로 꺾이는 느낌이 반복돼요.",
    "url": "https://www.hankyung.com/article/2021010599531",
    "url_title": "버티컬 마우스로 손목 건강 챙긴다 | 한국경제",
    "w7": {
      "where": "소파·침대 옆(팔이 자연스럽게 내려가지 않는 자세)",
      "while_": "손목이 몸쪽으로 꺾이는 느낌이 반복됨"
    },
    "nano_intent_candidates": [
      "노트북 중심 자세에서 손목이 꺾이지 않는 그립으로 바꾸기"
    ],
    "kbf_hints": [
      "손목을 덜 꺾이게 하는 수직(핸드셰이크) 그립 각도"
    ],
    "rtb": "\"소파나 침대 옆에 노트북을 두고 업무를 보다 보니, 손목이 몸쪽으로 꺾이는 느낌이 반복돼요\" (hankyung)"
  }
]
```

- `w7` キー: `why` / `when` / `where` / `while_` / `with_whom` / `with_what` / `how_feeling` — **quote が直接裏付けるフィールドのみを含める**(それ以外のキーは省略、null 埋め禁止)
- `nano_intent_candidates`: 0〜3 個。quote の内容のみで表現可能な目的
- `kbf_hints`: 0〜3 個。quote に言及/含意された具体的な属性のみ(数値は quote に存在する場合のみ)
- `url`/`url_title`: 本文の引用リンク、または `{{web_sources}}` からマッチ。不明の場合は空文字列

### Prompt テンプレート

````
# 役割
あなたは証拠キュレーションの専門家です。あなたの任務は、消費者リサーチのテキストを **verbatim な証拠ユニット(evidence unit)** へ分解することです — すべてのフィールドがソーステキストの正確な quote によって直接裏付けられる構造化レコードです。ソースに存在しない情報は決して追加しません。

# ソーステキスト (Product Research)
以下は **"{{product_name}}"** に関するウェブリサーチされた消費者コンテキストです。セクション見出しには番号が付いており(## N. ...)、N をセクション参照として使用してください。

{{product_research_sections}}

{{latent_intent_block}}

# ウェブソース (URL マッチング用)
{{web_sources_block}}

# タスク
ソーステキストを証拠ユニットへ分解してください。セクションごと、段落ごとに作業します:

1. 個別の消費者コンテキストを記述する各段落について、証拠ユニットを 1 個だけ抽出します。
2. `quote` = その段落から **verbatim** でコピーした文。正確にコピーしてください — 意訳、要約、異なる段落の文の結合、表現の「整形(clean up)」は決して行わないでください。
3. `source_ref` = "§N"、ここで N は quote が属するセクション番号です。
4. `url` / `url_title` = ソーステキストでその段落に付与された引用リンク(または ウェブソース から最も適合するもの)。不明の場合は "" を使用してください。URL を決して捏造しないでください。
5. `w7` = quote 自体が裏付ける次元のみを、可能な限り quote 自身の言葉を用いて記述:
   - why (動機) / when (時間) / where (場所) / while_ (並行する活動) / with_whom / with_what / how_feeling
   - **quote が裏付けないキーは省略してください。疎(sparse)なユニットが正しく、無理に埋めたユニットは誤りです。**
6. `nano_intent_candidates` = quote が述べる内容のみで表現できる消費者の目的を 0〜3 個。製品/カテゴリ名を繰り返さないでください。一般的な表現(「必要だ」「切らした」)は禁止。
7. `kbf_hints` = quote に言及された、または直接含意された具体的な製品属性を 0〜3 個(形態、構造、素材、機能)。数値は quote に verbatim で現れる場合のみ含めてください。
8. `rtb` = quote を再引用可能な形へ整え、引用符で囲み、短いソースタグを付けたもの。トリミングのみ — 語を決して追加・変更しないでください。

# ハードグラウンディングルール (違反したユニットは無効)
- quote はソーステキストに verbatim で存在しなければなりません。
- すべての w7 値、ナノインテント候補、KBF ヒントは、それが属する quote へ遡及可能でなければなりません — カテゴリに関するあなたの一般知識ではなく。
- 以下の 4 つのハルシネーションパターンは、出力のいかなる箇所でも厳格に禁止されます:
  1. **時間の断定 (Time assertion)**: ソースが述べていない期間/時点を追加する(例: "첫 주", "주말")。
  2. **存在しない場所 (Invented place)**: ソースが言及していない場所を追加する(例: "도서관")。
  3. **偽の引用 (Fake quotation)**: 意訳を、ソースで発話/記述されたかのように引用符で囲む。
  4. **存在しない行動 (Invented action)**: ソースが記述していない行動を記述する(例: "다시 검색")。
- 段落が曖昧すぎてどの w7 フィールドも裏付けられない場合は、quote + source_ref のみでユニットを出力してください(空の w7 オブジェクトは許可)。

# 言語
`quote`/`rtb` を除くすべてのフィールド値を **{{response_language}}** で記述してください。`quote`/`rtb` はソース言語を verbatim で保持しなければなりません。

# 出力ルール (厳格、JSON のみ)
- 有効な単一の JSON 配列のみを返してください。
- JSON を Markdown コードフェンスで囲まないでください(``` は不可)。
- JSON の外側に散文、説明、見出しを一切追加しないでください。
- 末尾のカンマを追加しないでください。すべてのキーと文字列値に二重引用符を使用してください。
- `unit_id` は数値でなければならず、1 始まりの連番です。
````

### 付録 — Dry-run 例(project 1328 §1 実データ)

Phase 3 成果物 §1 の実際の段落:

> 재택근무를 처음 시작했을 때(혼자 컴퓨터 앞에서 작업하는 시간이 길어질 때) 목·어깨 불편을 먼저 느끼고, 그다음엔 노트북 환경에서 "마우스까지 인체공학적으로 못 맞추는" 문제가 크게 와 닿아요. ([logitech.com](https://www.logitech.com/content/dam/logitech/ko/business/pdf/touchpads-vs-mice-ebook.pdf))

この段落が生成する証拠ユニット:

```json
{
  "unit_id": 2,
  "source_ref": "§1",
  "quote": "재택근무를 처음 시작했을 때(혼자 컴퓨터 앞에서 작업하는 시간이 길어질 때) 목·어깨 불편을 먼저 느끼고, 그다음엔 노트북 환경에서 \"마우스까지 인체공학적으로 못 맞추는\" 문제가 크게 와 닿아요.",
  "url": "https://www.logitech.com/content/dam/logitech/ko/business/pdf/touchpads-vs-mice-ebook.pdf",
  "url_title": "",
  "w7": {
    "why": "재택 전환으로 노트북 중심 작업이 길어짐",
    "while_": "목·어깨 불편을 먼저 느낌",
    "how_feeling": "'마우스까지 인체공학적으로 못 맞춘다'는 답답함"
  },
  "nano_intent_candidates": [
    "노트북 중심 자세에서 목·어깨-손목 부담을 함께 줄이기"
  ],
  "kbf_hints": [],
  "rtb": "\"노트북 환경에서 '마우스까지 인체공학적으로 못 맞추는' 문제가 크게 와 닿아요\" (logitech)"
}
```

注目点:
- `when` に「첫 주」のような期間が **ない** — ソースが「처음 시작했을 때」までしか述べていないため(AS-IS の Phase 4 はここで「첫 주」を作り出して warning を受けた)
- `how_feeling` の引用符付き引用がソース verbatim である — AS-IS の偽の引用(「손목도 마우스로 더 안 맞는 것 같다」)が根本から遮断される
- `kbf_hints` が空配列 — この quote には製品属性への言及がないため無理に埋めない(垂直グリップのヒントは §1 の hankyung quote ユニットから出る)

この 2 個のユニット(§1 logitech + hankyung)だけで Phase 4 が組み立てた結果が、`Hallucination_test/repropose/1328.json` の **CEP 4 修正案** と同一になることが、本工程の目標動作です。
