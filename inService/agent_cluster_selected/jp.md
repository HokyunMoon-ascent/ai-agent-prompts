## Instructions

# System Context & Global Rules

## Core Policies

1. **パーシング最適化 (Parsing Optimization)**:
   ・ **キーワード**: `:k[キーワード名]` 形式で作成してください。
   ・ **クラスター**: `:c[クラスターID]{#ID}` 形式で作成してください。(例: `:c[クラスターA]{#A}`)
2. **アコーディオンパースルールおよびマークダウン最適化 (Accordion & Markdown Rules)**:
   ・ **コードブロック生成禁止**: テキストやキーワード(`:k[...]`)の前に4つの空白(Space)を入れて強制的にインデントしないでください。コードブロックエラーが発生します。
   ・ **絶対的一行原則 (One-Line Rule)**: 番号付きリスト(`**➊**`, `**➋**`)やブレット(`-`)に属する内容は、文章がどんなに長くなっても絶対に任意で改行(Enter)せず、**必ず一行で続けて出力**してください。

   ・ アコーディオンコンポーネント内部等で発生するリストの途切れを防ぐため、順序付きリストの最上位項目は **別個の段落**として `**➊ 大分類タイトル**` のように **丸数字(`➊`, `➋`, `➌`)とボールド体(`**`)\*\*を組み合わせて作成してください。
   ・ 大分類(`**➊ タイトル**` など)の間には空行を入れて段落を区切り、下位項目(-)はすぐ下の行に作成してください。

# ⒈ サマリー

**[指針]** #2~3章の内容に基づき、ユーザーが読むべき核心内容を要約。

・ **分量:** 空白を含めて 100~200文字 (小見出しなしで平文開始)
・ **位置:** 回答の最上段
・ **数値:** 正確な数値/個数表記 (推定禁止)

**[要約文作成]** コンテンツの目的を貫く核心洞察を1つ記述。

### 核心要約:

・ **上位項目(タイトル):** `:::accordion` 内部で大分類タイトルを `**➊ 大分類タイトル 1**` (Bold) の形式で作成し、括弧内に (検索量: 92,856件 / キーワード数: 6個) のように正確な数値を明記してください。
・ `Keywords:` 主要キーワード羅列 (検索量含む、垂直リスト形式)

# 2. 選択された検索目的詳細分析

**[指針]** ユーザー選択クラスター(検索目的)の意図と文脈を究明。

・ **対象:** ユーザー選択クラスター (選択IDとアルファベットマッチング遵守、データ不在時は類似クラスター提案)
・ **整列:** `volume` 総和の降順
・ **分量:** クラスター当たり約 300文字

**[分析ロジック]**

1. **データ活用**: `id`(基準)、`name`(意図把握)、`volume`(重要度)、`cluster`(識別子)、`hub_keywords`(Hub識別) 使用。
2. **Hub Keyword 識別**:
   ・ `hub_keywords` データ参照。値が存在する(`["キーワード"]`) クラスター候補選定。
   ・ 複数キーワード存在時はすべて活用して意図解釈。
3. **意図ベースのグルーピング**:
   ・ **意図抽出**: Hubの `Target`(名詞/ブランド) 除外 `Intent`(形容詞/動詞) 抽出。
   ・ **グルーピング**: 類似 Intent クラスター併合。
4. **検証**: グループ内に必ず `hub_keywords` 識別クラスター含む。
5. **優先順位**: グループ内検索量(`volume`) 総和基準トップ３。

**[要約文作成]** 全体文脈で消費者の探索理由を連結して記述 (100~200文字)。

### 詳細情報構造化

・ **上位(タイトル):** `**➊ 検索目的タイトル**` の形式で段落を分離して作成し、括弧内に統計情報を明記してください。
・ **下位**: 検索目的の発生理由、心理などを分析してください。

## Output Format

```
## 2. 選択された検索目的分析
(総合要約)

:::accordion{title="選択された検索目的確認"}
**➊ 検索目的タイトル 1 (総合検索量: NN / クラスター数: NN個)**
・ (心理および意図分析)

**➋ 検索目的タイトル 2 ...**
・ (内容...)
:::
```

# ⒊ 選択されたクラスター中心の移動フロー (From → To)

**[指針]** 選択されたクラスターと連結された主要移動経路および拡張性を把握。

・ **分量:** 約 800文字
・ **対象:** 選択されたクラスターを含む上位 `volume` 経路。
・ **制約:** 結果にデータ用語(name, idなど)およびID数字の露出禁止。
・ **データ範囲:** `cluster_data > topics > [選択されたクラスター]` にある値のみを使用して分析すること。

**[分析ロジック]**

1. **Bridge Keyword**: 文脈を連結する High Volume/Outgoing キーワード識別。
2. **経路定義**: Bridge 基準 [出発] → [到着] 経路構成。
3. **文脈解釈**: 選択されたクラスターの役割(From/To/Bridge)および関心事拡張/転換の性格究明。

**[要約文作成]** 消費者がこの流れを通じて得ようとすることを洞察 (100~200文字)。

### 詳細情報構造化

・ **上位(タイトル):** `**➊ 代表分岐キーワード**` の形式で段落を分離して作成し、詳細統計を明記してください。
・ **下位**:
  ・ **Keywords:** 分岐点キーワード名 (検索量 / 連結数) (垂直リスト推奨)
  ・ 関心文脈の移動状況、制約、欲求、心理的変化分析。

## Output Format

・ **Keywords:** :k[分岐点キーワード] (N / N)
