# 작업 목표

agent_aiOpt_owned 프롬프트의 출력을 **토픽 그룹 단위의 정보구조(IA) 제안 1섹션**으로 통합 재설계합니다.

## 수정

기존 v.0.2.2는 4섹션(분석 개요 · 갭 진단 요약 · 개선 제안 · 인사이트) 구조와 갭 단위 5요소 묶음(추가 위치 · 콘텐츠 형태 · 헤딩 · 핵심 문장 · 기대 효과) 출력으로 정보량이 많고 컨설팅 의뢰자가 한눈에 잡기 어렵습니다. 실무자 인터뷰 결과 H1/H2 헤더 단위의 큰 토픽 묶음만 받기를 원했고, 디테일한 카피·핵심 문장은 활용도가 낮다는 피드백을 받았습니다. 신규 버전은 다음을 달성합니다.

- 분석 개요 · 갭 진단 요약 · 인사이트 3섹션을 **프롬프트 본문에서 통째로 삭제** (출력에 안 쓰므로 섹션 정의 자체가 불필요)
- 인사이트의 핵심 메시지 1문장은 **개선 제안 리드 문단에 자연어로 흡수**
- 갭 분류·자사 페이지 무게중심 정리·구조적 약점 진술 등은 **작업 단계의 사고 가이드로만 사용**, 별도 산출 강제 없음
- 갭 단위 5요소 묶음을 폐기하고, **토픽 그룹 단위로 H1 + H2(2~3개) IA만 제공**
- 콘텐츠 형태·핵심 문장·기대 효과 필드는 제거 (실무자가 H1/H2만 받고 싶다는 피드백 반영)
- 흡수 방식은 **"신규 페이지" / "기존 페이지 보강" 2값으로 단순화** (페이지 유형 표기 제거)
- 컨설팅 의뢰자가 한 번에 읽히도록 어려운 용어 추방, **토픽명 그대로 노출**
- 토픽 그룹 수는 **3~5개 유연**, 그룹 라벨은 토픽명만 굵게 (A·B·C·D 알파벳 prefix 제거)

## 출력 구조 규칙

### 노출 섹션

- "개선 제안" 1섹션만 출력합니다.
- **분석 개요·갭 진단 요약·인사이트 섹션은 프롬프트 본문에 정의하지 않습니다.** 출력에 사용되지 않으므로 별도 산출 형식을 지시하지 않으며, 모델이 거기에 토큰을 쓰지 않도록 합니다.
- 자사 페이지 무게중심·갭 분류·구조적 약점 진술은 작업 단계 안에서 사고 가이드로만 사용합니다. 별도 정리·산출 없이 토픽 그룹화와 리드 문단 작성에 직접 흡수합니다.
- 인사이트의 핵심 메시지 1문장은 리드 문단 작성 단계에서 자연어로 합쳐 한 번에 처리합니다.

### 리드 문단 규칙

- 표가 시작되기 전 본문 단락 1개에 다음 3가지 정보를 자연어로 통합합니다.
  - 자사 페이지가 비어 있는 토픽 흐름(토픽명을 직접 노출)
  - 그래서 어떤 의미인지의 한 줄 통찰 (인사이트 흡수 자리)
  - 토픽 그룹 수와 흐름 요약
- 리드 문단에서 "신규 N개 + 보강 M개" 같은 표 결과 합산 숫자를 미리 단정하지 않습니다. 흡수 방식 결과는 표가 보여줍니다.

### 토픽 그룹 정의 원칙

- AI 응답에서 추출한 세부 토픽을 **자사 콘텐츠 제작 액션 단위**로 묶어 3~5개 토픽 그룹으로 통합합니다.
- "한 페이지(또는 한 섹션)로 함께 다룰 수 있는 토픽"이 같은 그룹에 속해야 합니다.
- 각 그룹은 자사가 실행할 콘텐츠 액션과 1:1로 매칭됩니다 (= 1 그룹 → 1 신규 페이지 또는 1 기존 페이지 보강).
- 그룹 라벨은 토픽명만 굵게 표기합니다 (A·B·C·D 등 알파벳 prefix 미사용).

### 표 구조

**표 ➊ — 토픽 그룹 정의 (3열)**

| 토픽 그룹    | 묶인 세부 토픽   | 흡수 방식                      |
| ------------ | ---------------- | ------------------------------ |
| **(그룹명)** | (세부 토픽 나열) | 신규 페이지 / 기존 페이지 보강 |

- "묶인 세부 토픽" 셀: AI 응답에서 다뤄진 세부 토픽명을 `/` 또는 `·`로 구분해 자연어로 나열, `:k[..]` 미사용.
- "흡수 방식" 셀: **"신규 페이지" 또는 "기존 페이지 보강" 2값만 허용**. 페이지 유형(PDP/FAQ/Blog/Spec/Comparison) 표기 금지.

**표 ➋ — 토픽 그룹별 정보구조(IA) 제안 (3열)**

| 토픽 그룹    | H1 후보   | H2 후보 (2~3개)          |
| ------------ | --------- | ------------------------ |
| **(그룹명)** | (H1 문안) | (H2-1) / (H2-2) / (H2-3) |

- "H1 후보" 셀: 실제 사용할 페이지/섹션 H1 문안 1개를 자연어로 작성.
- "H2 후보" 셀: 2~3개를 `/`로 구분해 자연어로 나열.
- 두 셀 모두 `:k[..]` 인용 미사용 (인용 강제는 글머리 기호 해설 단계에서만 적용).

### 해설 작성 규칙

- 표 ➋ 직후 글머리 기호 기반 해설을 배치합니다.
- 각 토픽 그룹마다 다음 구조로 작성합니다.
  - **메인 불릿**: 토픽 그룹의 핵심 메시지(굵게), "토픽" 단어를 명시적으로 노출
  - **하위 불릿 2~3개**: AI 응답·자사 페이지 인용을 `:k[..]`로 명시한 근거
  - **마지막 하위 불릿 1줄**: "신규 페이지로 가는 이유" 또는 "기존 페이지 보강으로 가는 이유" + 어디에 들어가는지 위치 메모
    - 신규 페이지로 가는 이유: 세부 토픽이 한 페이지로 묶일 만한 분량 + 자사 페이지 본질과 결이 다름
    - 기존 페이지 보강으로 가는 이유: 토픽이 특정 페이지 본질에 가까움 + 별도 분리 시 주된 내용이 흩어짐
- 마지막에 "**종합** — ..." 1문장으로 마감합니다.
- 해설 전체 분량은 600자 내외를 유지합니다.

## 톤 규칙 (마케터·컨설팅 의뢰자 친화)

다음 표현은 출력에서 추방하고 쉬운 표현으로 대체합니다.

| 금지 표현                                            | 권장 표현                             |
| ---------------------------------------------------- | ------------------------------------- |
| 효익 진술 (일변도)                                   | 제품의 좋은 점 (만 강조)              |
| 결정 직전 인용원                                     | AI가 답할 때 참고하는 자료            |
| 구조적 약점                                          | (생략, 또는 "약한 부분")              |
| 균형 인용 신호                                       | 장단점을 같이 보여주는 안내           |
| 무게중심                                             | 주된 내용                             |
| 결정 직전 단서                                       | 살지 말지 결정하기 직전에 찾는 정보   |
| 정합성                                               | 어울림 / 자연스러움                   |
| 흡수 가능성                                          | 페이지에 들어갈 만한 정도             |
| KBF / RTB / PDP / FAQ / Blog / Spec / Comparison     | (자연어 위치·헤딩 표현으로 풀어 쓰기) |
| 매트릭스 / 사분면 / 4축 / 5분류 / 프레임 / 톤 / 차원 | (출력 본문에서 추방)                  |

**추상명사로 토픽을 묶지 않습니다.**

- 금지: "시간 축·환경·시나리오·균형 신호 4개 흐름"
- 권장: "**적응 기간 / 사용 환경 / 좌·우 페어 운용 / 부적합 안내** 토픽"

## 작업 단계 (내부 처리 — 별도 산출 형식 없이 사고 가이드로만 사용)

1. **CEP 프롬프트 의도 단서 추출**: 어떤 상황·맥락의 질문인지, 결정 기준이 되는 정보 단서를 정리.
2. **AI 응답에서 의미 영역 수집**: 응답이 다룬 엔티티(브랜드·제품·속성·수치·시나리오)와 토픽(검토 기준·대안·의사결정 가이드 등)을 수집.
3. **자사 페이지 점검 (의미 일치 원칙 기반 갭 확정)**: 자사 페이지의 무게중심을 파악하면서 동시에 각 의미 영역에 대해 자사 페이지에 의미적으로 동등한 내용이 있는지 검토. 있으면 갭 아님. (무게중심·4관점 분류는 별도 정리·산출 없이 다음 단계로 직접 이관)
4. **토픽 그룹화**: 갭 확정된 의미 영역을 자사 콘텐츠 제작 액션 단위로 묶어 3~5개 토픽 그룹으로 통합. "한 페이지(또는 한 섹션)로 함께 다룰 수 있는 토픽"이 같은 그룹이 되도록 묶음.
5. **흡수 방식 결정**: 각 토픽 그룹별로 "신규 페이지" 또는 "기존 페이지 보강" 중 하나로 판단.
6. **IA 작성**: 각 토픽 그룹별 H1 후보 1개 + H2 후보 2~3개를 자연어로 작성.
7. **리드 문단 작성**: 토픽 흐름 + 자사 콘텐츠의 약한 부분 한 줄 통찰을 자연어로 합쳐 리드 문단 1단락 작성. (인사이트의 핵심 메시지가 여기서 한 번에 흡수됨)
8. **자체 점검**: 아래 체크리스트 전부 통과 확인.

## 자체 점검 체크리스트

1. 출력 섹션이 "개선 제안" 1개만인가? (4섹션 노출 금지)
2. 토픽 그룹 수가 3~5개 범위 안인가?
3. 표 ➊·➋ 셀에 `:k[..]` 인용이 들어가 있지 않은가?
4. "흡수 방식" 셀이 "신규 페이지" 또는 "기존 페이지 보강" 2값만인가? (페이지 유형 표기 없음)
5. 그룹 라벨이 토픽명만 굵게이고 알파벳 prefix(A·B·C·D)가 노출되지 않았는가?
6. 글머리 기호 해설의 모든 `:k[..]`가 자사 페이지·AI 응답에 실재하는 표현인가?
7. 각 토픽 그룹 해설 끝에 "신규/기존 결정 근거" 1줄이 위치 메모와 함께 있는가?
8. 추상명사 묶음 표현(예: "X 축·Y 신호·Z 흐름") 대신 토픽명을 직접 노출했는가?
9. 어려운 용어(효익·정합성·무게중심·결정 직전 인용원·KBF·RTB·PDP 등)가 출력 본문에 없는가?
10. 리드 문단에 인사이트의 핵심 1문장이 자연어로 흡수되어 있는가?
11. 메인 불릿에 "토픽" 단어가 명시적으로 등장하는가?
12. 누락 only 원칙: 자사 페이지가 이미 다루는 영역이 토픽 그룹에 섞여 있지 않은가?
13. 의미 일치 원칙: 표현이 다르다는 이유만으로 갭으로 분류한 항목이 없는가?

## 입출력 정합성

- **입력**:
  - `{{page_content_A}}` — 자사 페이지 콘텐츠
  - `{{user_prompt_B}}` — CEP 프롬프트
  - `{{ai_responses_C}}` — AI 응답 1~3개
  - (선택) `{{gap_analysis_output}}` — 갭 분석의 "통합형 권장" (사용 가능 시 토픽 그룹화 출발점으로 활용, 미입력 시 AI 응답에서 직접 추출)
- **출력**: 개선 제안 1섹션
  - 리드 문단 1개
  - 아코디언 안에 표 ➊ + 표 ➋ + 글머리 기호 해설
- **다음 에이전트 입력으로의 흐름**: 본 에이전트의 출력은 콘텐츠 제작 브리프 입력으로 직접 사용 가능해야 합니다. H1·H2와 위치 메모만 보고도 콘텐츠 제작 액션이 분명히 잡혀야 합니다.

## 설계 비-목표

- 본문 카피 작성 — H1/H2 IA만 제공, 본문 단락 초안은 별도 샘플 에이전트의 영역.
- 학술적 갭 5분류(카테고리/속성/CEP/관계/신뢰) 매핑 노출 — 4관점은 내부 분류로만 사용.
- 페이지 유형(PDP/FAQ/Blog/Spec/Comparison) 라벨 표기 — 흡수 방식은 2값으로만.
- noneURL 모드 분기 — 본 변경에서는 자사 URL 있음 모드만 다룸. noneURL은 별도 작업으로 분기.
