1. 분석 개요
   AI 검색 질문의 사용자는 "손목 뻐근함의 원인이 자세인지 빠르게 테스트하고 싶다"는 의도로 50~70° 버티컬 + 좌/우 대응 + 엄지 측면 버튼 + 후기 RTB까지 한 번에 묻는데, 자사 페이지는 제품별 핵심 기능 설명에 집중되어 있어 체감 타임라인·환경 가이드·외부 후기 RTB·"좌/우 번갈아 사용" 시나리오 매칭 영역이 결손되어 있다.
   :::accordion{title="개요 확인"} ➊ AI 검색 질문의 사용자 의도(CEP) 요약
   CEP: "일반 마우스로 손목 뻐근함 → 자세 원인인지 빠르게 테스트"하려는 즉시 검증형 구매 검토
   KBF 단서: :k[버티컬], :k[손목이 꺾이는 느낌], :k[좌/우 선택], :k[엄지 측면 버튼], :k[후기/입소문]
   RTB 단서: 실제 통증이 줄었다는 후기·입소문·사용자 체감 보고
   ➋ AI 응답이 공통적으로 다룬 의미 영역 (공통 영역)
   체감 타임라인: :k[즉각 효과 (1~3일)], :k[적응 기간 (3~7일)], :k[장기 효과 (2주+)], :k[1~2주 적응 기간]
   자세·환경 동반 가이드: :k[책상 높이(팔꿈치 각도)·마우스 간격], :k[팔꿈치 90도], :k[손목 뜨게], :k[마우스 높이 낮추기]
   외부 후기·리뷰 매체 RTB: :k[건초염이 없어졌다], :k[carpal tunnel pain 줄었다], :k[다나와]
   좌/우 번갈아 사용 시나리오: :k[양손 번갈아 쓰는 스타일이면 거의 필수 후보], :k[좌/우 각각 모델 있음]
   빠른 테스트용 솔직한 단점 인정: :k[처음 2~3일은 오히려 어색함], :k[게임용으로는 부적합], :k[작은 손이면 큰 모델 불편]
   ➌ 자사 페이지의 무게중심
   자사 페이지는 :k[57° 손목이 편한 각도], :k[근육 긴장 10% 줄여주고], :k[자세 교정] 같은 자체 주장 기반 인체공학 효과 설명과 :k[Lift], :k[MX Vertical], :k[MX ERGO] 라인업 소개에 무게중심이 있음
   좌/우 모델 존재 사실(:k[왼손, 오른손 어디에나 딱 맞는 Lift], :k[왼손용도 있어요])과 손 크기 매칭(:k[조금 작거나 보통 크기의 손에 잘 맞아요])은 페이지 내에 존재
   ➍ 갭 한 줄 통찰
   자사 페이지는 "제품 자체의 효익 설명"은 있으나 "사용자가 결정 직전에 필요한 체감 타임라인·환경 가이드·외부 후기 RTB·좌/우 번갈아 시나리오"가 부재해 AI 응답 구성 단계에서 자사 라인업 일부(Lift, MX ERGO)가 호출되지 못하고 있다 :::
2. 브랜드 노출 분석
   자사 브랜드는 :k[Logitech MX Vertical] 한 모델만 모든 AI 응답에서 1순위로 노출되었고, :k[Lift]·:k[MX ERGO]는 어느 응답에도 직접 호출되지 않아 라인업 단위 가시성에서 명확한 결손이 확인된다.
   :::accordion{title="브랜드 노출 확인"} ➊ 자사 브랜드 노출 현황
   노출 여부: 부분 노출 (MX Vertical만 노출, Lift·MX ERGO 미노출)
   노출 위치: AI 응답 1번·2번·3번 모두에서 :k[Logitech MX Vertical]을 1순위 또는 표준 모델로 인용
   미노출 모델: :k[Lift](좌/우 전용 시나리오에 부합함에도 호출 안 됨), :k[MX ERGO](트랙볼 대안 맥락에서 :k[Kensington Orbit Trackball]에 자리를 내줌)
   ➋ 자사 외 브랜드 노출 패턴
   Kensington: 등장 응답 — AI 응답 1번, AI 응답 3번 / 인용 근거 — :k[약 47° 바디 각도], :k[왼손 전용 모델], :k[손목 뜨게] 같은 각도·전용 라인업·트랙볼 대안 신호
   CHERRY MW 4500: 등장 응답 — AI 응답 1번 / 인용 근거 — :k[추가 엄지 버튼 2개], :k[좌/우 클릭 기능 전환 스위치]
   Perixx PERIMICE-713: 등장 응답 — AI 응답 2번 / 인용 근거 — :k[좌/우 각각 모델 있음], :k[양손 번갈아 쓰는 스타일이면 거의 필수 후보]
   ELECOM Shellpha: 등장 응답 — AI 응답 2번 / 인용 근거 — 손 작은 편 슬림 그립 + 무소음 옵션
   Evoluent VerticalMouse 4: 등장 응답 — AI 응답 3번 / 인용 근거 — :k[거의 수직에 가까운 각도], :k[좌/우 각각 모델 있음]
   ➌ 자사 브랜드 미노출/약노출 가설
   신호 부재 1 — 좌/우 번갈아 사용 시나리오 매칭 부재: 자사 페이지의 Lift 영역은 좌/우 모델이 별도로 존재한다는 사실은 명시하나, "좌/우 번갈아 사용 사용자가 좌/우 각 모델을 페어로 운영하는 시나리오"를 가이드 형태로 다루지 않아 AI 응답 2번·3번이 같은 시나리오를 :k[Perixx PERIMICE-713]·:k[Evoluent VerticalMouse 4]로 채움
   신호 부재 2 — 외부 후기·리뷰 매체 RTB 부재: 자사 페이지는 :k[근육 긴장 10% 줄여주고], :k[사용자 테스트 완료. 인체공학자 인증.] 같은 자체 주장 신호만 있고 :k[건초염이 없어졌다] 같은 외부 후기·매체 인용이 없어, AI 응답 생성 단계에서 RTB 인용 후보가 되지 못함
   신호 부재 3 — 트랙볼=손목 부담 완화 대안 맥락의 외부 위치 부재: MX ERGO 영역은 :k[손목의 부담을 덜어주어] 효익을 설명하나, "버티컬을 못 쓸 때의 트랙볼 대안" 시나리오에서 외부 인용 가능한 형태로 신호가 형성되지 않아 AI 응답 3번에서 :k[Kensington Orbit Trackball]에 자리를 내줌 :::
3. 의미적 갭 매핑
   3개 응답 모두에서 일관되게 등장하지만 자사 페이지에 의미적으로 부재한 4개의 공통 갭과, 일부 응답에만 등장한 3개의 차이 갭이 도출되었다.
   :::accordion{title="의미적 갭 확인"} ➊ [공통 갭] 체감 타임라인 가이드 — "언제부터 통증이 덜한지" 단계별 안내
   AI 응답 근거: AI 응답 1번·2번·3번 모두 — :k[1~2주 적응 기간], :k[즉각 효과 (1~3일)], :k[적응 기간 (3~7일)], :k[장기 효과 (2주+)]
   자사 페이지 점검: 자사 페이지에 적응 기간·체감 변화 시점에 대한 언급이 전혀 없음. :k[근육 긴장 10% 줄여주고] 같은 효익 주장은 있으나 시간 축 가이드는 부재
   필요 엔티티 후보: 적응 단계 라벨(:k[즉각 효과 (1~3일)], :k[적응 기간 (3~7일)], :k[장기 효과 (2주+)])
   필요 토픽 후보: 단계별 체감 변화 가이드, "처음 N일은 어색할 수 있음" 솔직 안내, 적응 가속 팁
   AI 노출 저해 가설: 사용자가 결정 직전 가장 알고 싶은 "지금 사면 언제부터 덜 아프냐"의 답을 자사 페이지가 제공하지 않아 AI가 이 영역의 출처를 외부 매체에서 가져오게 됨
   ➋ [공통 갭] 자세·환경 동반 가이드 — 마우스만 바꿔서는 한계라는 신호
   AI 응답 근거: AI 응답 1번·3번 — :k[책상 높이(팔꿈치 각도)·마우스 간격], :k[팔꿈치 90도], :k[손목 뜨게], :k[마우스 높이 낮추기]
   자사 페이지 점검: 자사 페이지에 자세·책상·팔 지지 같은 사용 환경 가이드가 부재. 제품 단독 효익 설명 중심
   필요 엔티티 후보: :k[팔꿈치 90도], :k[손목 뜨게], :k[마우스 높이 낮추기], 책상 높이·마우스 간격
   필요 토픽 후보: 환경 동반 체크리스트, "마우스 + 자세 + 책상" 3요소 가이드, 잘못된 자세 예시 vs 올바른 자세
   AI 노출 저해 가설: AI는 "통증 감소" 질문을 받을 때 마우스 단독이 아닌 환경 가이드까지 묶어 답하는 경향이 있어, 환경 가이드가 없는 페이지는 응답 구성에서 부분 인용으로 그치게 됨
   ➌ [공통 갭] 외부 후기·리뷰 매체 RTB 인용 영역
   AI 응답 근거: AI 응답 1번·2번·3번 모두 외부 매체 인용 — :k[다나와], :k[건초염이 없어졌다], :k[carpal tunnel pain 줄었다] 등 전문 매체·커뮤니티·사용자 후기를 직접 인용
   자사 페이지 점검: 자사 페이지에 :k[사용자 테스트 완료. 인체공학자 인증.] 같은 자체 검증 문구는 있으나, 외부 매체·커뮤니티·실제 사용자 후기 인용이 부재 — 의미적으로 인접하지만 RTB 종류가 다름
   필요 엔티티 후보: 전문 매체 리뷰 인용, 커뮤니티 후기 인용, 임상/사용 사례 인용
   필요 토픽 후보: 후기·매체 인용 박스, "통증이 줄었다" 사용자 보고 모음, 매체 리뷰 요약
   AI 노출 저해 가설: AI는 RTB 신호로 외부 매체를 우선 인용하므로, 자체 주장만 있는 페이지는 RTB 출처가 되지 못해 답변 본문에 자사 페이지 링크가 자리잡지 못함
   ➍ [공통 갭] "좌/우 번갈아 사용" 시나리오 매칭 — 라인업 가시성 문제
   AI 응답 근거: AI 응답 1번·2번·3번 — :k[양손 번갈아 쓰는 스타일이면 거의 필수 후보], :k[좌/우 각각 모델 있음], :k[왼손 전용 모델]을 시나리오 단위로 묶어 추천
   자사 페이지 점검: 자사 페이지에 :k[왼손, 오른손 어디에나 딱 맞는 Lift], :k[왼손용도 있어요]는 있으나 "좌/우 번갈아 사용자에게 좌/우 각 모델을 페어로 운영"이라는 시나리오 가이드는 부재 — 부분 의미 일치이지만 시나리오 매칭은 결손
   필요 엔티티 후보: :k[Lift] 왼손/오른손 페어, :k[좌/우 각각 모델 있음] 라인업 신호
   필요 토픽 후보: "좌/우 번갈아 사용자" 시나리오 페이지 또는 Lift 페어 운용 가이드
   AI 노출 저해 가설: 사용자 의도(좌/우 번갈아) → 라인업 매칭이 페이지에서 시나리오로 묶이지 않아 AI는 같은 시나리오를 :k[Perixx PERIMICE-713]·:k[Evoluent VerticalMouse 4] 같은 외부 라인업으로 채움
   ➎ [차이 갭] 빠른 테스트 추천 조합 — 단일 모델 추천이 아닌 "조합" 안내
   등장 응답: AI 응답 2번에만 명확히 등장 — "MX Vertical (메인) + Perixx (좌/우 교차 테스트용)" 같은 조합 추천
   자사 페이지 점검: 자사 페이지는 모델별 단독 영역 구성. 사용자 시나리오에 따른 "조합 운용" 안내 부재
   필요 엔티티 후보: 메인 모델 + 보조 모델 페어 라벨
   필요 토픽 후보: 시나리오별 조합 추천, "각도 문제인지 / 좌·우 사용 때문인지 둘 다 확인 가능" 검증 시나리오
   AI 노출 저해 가설: 사용자가 "원인 검증"을 목적으로 둘 때 조합 답을 AI가 만들고, 자사 페이지는 단일 모델 답에 한정되어 호출됨
   ➏ [차이 갭] 솔직한 단점·한계 인정 — 신뢰도 신호
   등장 응답: AI 응답 2번 — :k[처음 2~3일은 오히려 어색함], :k[작은 손이면 큰 모델 불편], :k[게임용으로는 부적합]
   자사 페이지 점검: 자사 페이지에 한계·단점 언급이 없음. 효익 일변도 메시지
   필요 엔티티 후보: 비적합 시나리오, 적응기 어색함, 작은 손/큰 모델 미스매치
   필요 토픽 후보: "이런 경우엔 부적합" 솔직 카피, 비적합 시나리오 안내
   AI 노출 저해 가설: AI는 균형 잡힌 답변을 위해 단점도 함께 인용하는데, 자사가 단점을 다루지 않으면 단점 인용은 외부에서 가져오게 되어 답변 내 자사 비중이 떨어짐
   ➐ [차이 갭] 손 크기별 모델 매칭 가이드
   등장 응답: AI 응답 2번·3번 — :k[작은 손이면 큰 모델 불편], "ELECOM은 손 작은 편", "MX Vertical은 크고 무거움"
   자사 페이지 점검: 자사 페이지의 Lift 영역에 :k[조금 작거나 보통 크기의 손에 잘 맞아요]가 부분적으로 존재. 다만 MX Vertical 측에서 "큰 손에 적합/작은 손엔 부적합"식 매칭 신호는 부재 — 부분 의미 일치, 매칭 표준화는 결손
   필요 엔티티 후보: 손 크기 라벨(작은/보통/큰), 모델별 손 크기 권장
   필요 토픽 후보: 손 크기 매칭 가이드, "내 손에 맞는 모델 고르는 법"
   AI 노출 저해 가설: 사용자가 "내 손 크기"를 변수로 둘 때 매칭 가이드가 결손되어 AI가 외부 라인업까지 끌어옴 :::
4. 보강 권장사항
   도출된 7개 갭 중 체감 타임라인·환경 가이드·손 매칭·라인업 시나리오는 기존 페이지 보강(통합형)으로, 외부 후기 RTB·통합 인체공학 허브는 별도 페이지/외부 영역(분리형)으로 가는 것이 적합하다.

   대상 갭: 의미적 갭 매핑의 ➊ 체감 타임라인 가이드
   보강 방향: 각 제품 상세 영역에 적응 단계별 체감 변화 안내 영역을 갖추어, 사용자가 결정 직전 시간 축 기대치를 형성할 수 있는 콘텐츠가 있어야 함
   엔티티 후보: :k[즉각 효과 (1~3일)], :k[적응 기간 (3~7일)], :k[장기 효과 (2주+)]
   토픽 후보: 단계별 체감 변화, 적응 가속 팁
   채널 힌트: 온드 + 샘플 (페이지 영역 + 짧은 카피)
   통합 판단 근거: 제품 단위로 체감 타임라인이 다르지 않아 각 제품 영역의 효익 설명 옆에 동일 패턴으로 보강하는 것이 자연스러움
   ➋ [통합형] 자세·환경 동반 가이드 보강 (제품 영역 또는 라인업 허브)
   대상 갭: 의미적 갭 매핑의 ➋ 자세·환경 동반 가이드
   보강 방향: "마우스만 바꿔서는 한계, 자세·책상·팔 지지가 함께 잡혀야 한다"는 메시지를 페이지 내 짧은 가이드로 보강해야 함
   엔티티 후보: :k[팔꿈치 90도], :k[손목 뜨게], :k[마우스 높이 낮추기], 책상 높이·마우스 간격
   토픽 후보: 환경 체크리스트, 잘못된/올바른 자세 비교
   채널 힌트: 온드
   통합 판단 근거: 환경 가이드 자체는 제품군 공통이므로 라인업 상위 가이드 영역에 통합하는 편이 효율적
   ➌ [분리형] 외부 후기·리뷰 매체 RTB 허브 (Ergo Series 별도 페이지)
   대상 갭: 의미적 갭 매핑의 ➌ 외부 후기·리뷰 매체 RTB 인용 영역
   보강 방향: 자체 주장과는 별도로, 외부 매체 리뷰·커뮤니티 후기·실제 사용자 통증 감소 보고를 모은 RTB 허브가 별도 페이지로 존재해야 함
   엔티티 후보: 전문 매체 리뷰 인용, 사용자 후기 인용, 임상/사례 인용
   토픽 후보: 매체 인용 모음, 후기 사례 모음
   채널 힌트: 언드 + 온드 (외부에서 형성된 콘텐츠를 자사 페이지에서 큐레이션)
   분리 판단 근거: 외부 후기·리뷰 인용은 제품별 효익 페이지에 분산되면 RTB 신호가 약해지므로, 라인업 단위 허브로 분리해 외부 검색 가시성을 모아주는 편이 유리
   ➍ [통합형] 좌/우 번갈아 사용 시나리오 매칭 (Lift 영역)
   대상 갭: 의미적 갭 매핑의 ➍ 좌/우 번갈아 사용 시나리오
   보강 방향: Lift 영역에 "좌/우 번갈아 쓰는 사용자가 왼손/오른손 모델을 페어로 운용하는" 시나리오 가이드를 보강해야 함
   엔티티 후보: :k[Lift] 왼손/오른손 페어, :k[좌/우 각각 모델 있음]
   토픽 후보: 좌/우 번갈아 사용자 시나리오 가이드, 페어 운용 안내
   채널 힌트: 온드 + 언드 (페이지 보강 + 외부 리뷰 매체에 같은 시나리오 신호 형성)
   통합 판단 근거: 시나리오 매칭은 Lift 라인업 본질에 가까워 별도 페이지보다 Lift 영역 내 시나리오 단락으로 통합하는 편이 자연스러움
   ➎ [분리형] 통합 인체공학 가이드 페이지 (자세 + 환경 + 적응 기간)
   대상 갭: ➊ + ➋ + ➐ 묶음 (체감 타임라인·환경 가이드·손 크기 매칭)
   보강 방향: 제품 영역에서 분산된 가이드 신호를 모아 "버티컬·트랙볼 입문" 통합 가이드 허브를 별도 페이지로 두어 AI 응답이 자사 도메인 내부에서 가이드 영역을 인용할 수 있게 만들어야 함
   엔티티 후보: 적응 단계, 자세 요소, 손 크기 라벨, 라인업 매칭
   토픽 후보: 입문 가이드, 단계별 체크리스트
   채널 힌트: 온드
   분리 판단 근거: 가이드 신호가 여러 제품에 공통이므로 단일 허브로 분리해야 외부 검색에서 "가이드"라는 의도 매칭이 일어남
   ➏ [통합형/샘플] 솔직한 단점·한계 인정 카피 (제품 영역 단점 단락)
   대상 갭: 의미적 갭 매핑의 ➏ 솔직한 단점·한계 인정
