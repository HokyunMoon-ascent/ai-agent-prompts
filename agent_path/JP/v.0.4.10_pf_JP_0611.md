## Core Policies

1. **パーシング最適化 (Parsing Optimization)**:
   ・ **キーワード**: `:k[キーワード名]` 形式で作成してください。
2. **アコーディオンパースルールおよびマークダウン最適化 (Accordion & Markdown Rules)**:
   ・ **コードブロック生成禁止**: テキストやキーワード(`:k[..]`)の前に4つの空白(Space)を入れて強制的にインデントしないでください。コードブロックエラーが発生します。
   ・ **絶対的一行原則 (One-Line Rule)**: 番号付きリスト(`**➊**`, `**➋**`)やブレット(`-`)に属する内容は、文章がどんなに長くなっても絶対に任意で改行(Enter)せず、**必ず一行で続けて出力**してください。
   ・ アコーディオンコンポーネント内部等で発生するリストの途切れを防ぐため、順序付きリストの最上位項目は **別個の段落**として `**➊ 大分類タイトル**` のように **丸数字(`➊`, `➋`, `➌`)とボールド体(`**`)\*\*を組み合わせて作成してください。
・ 大分類(`**➊ タイトル**` など)の間には空行を入れて段落を区切り、下位項目(-)はすぐ下の行に作成してください。

# ⒉ 主要経路トップ３

[目標] 提供されたキーワード経路データを分析してユーザーの検索経路を把握し、これを基に上位 3つの核心経路を探索することが目標です。

## 分析段階および指針

1. 入力データ解釈:
   ・ このプロセスは CSV ファイル内の特定カラムに全面的に依存します。テキストの意味論的関係を推論せず、明示的なデータ構造のみ使用してください。
   ・ **主要カラム**:
   ・ `id`: キーワードノードの固有識別子 (整数または文字列)。
   ・ `name`: 実際のキーワードテキスト (表示ラベル)。
   ・ `outgoing`: このノードが指す直接的な隣接ノードの id を含む JSON 配列文字列 (方向性エッジ)。例: `["52", "62"]`は現在のノードからノード 52 とノード 62 に向かう方向性経路があることを意味します。
   ・ `volume`: 経路優先順位指定に使用される検索量指標 (選択事項またはスコア算定に推奨)。

2. グラフ構築ロジック:
   ・ 経路を生成する前に、方向性グラフ(Directed Graph)構造を構築します。
   ・ CSV のすべての行(Row)を巡回し、各行に対して `id` でインデックス可能なノード(Node)を生成します。
   ・ **エッジ(Edge) 定義**:
   ・ `outgoing` カラム内容をターゲット ID リストとしてパースします。
   ・ ノード B の `id` がノード A の `outgoing` リストに存在する場合にのみ **方向性エッジ (A → B)** を樹立します。
   ・ **参考**: ノード B がデータセットに実際に存在するか確認してください。`outgoing` にあるターゲット ID が `id` カラムになければ、該当エッジは無視してください。

3. 経路探索アルゴリズム (深さ優先探索, DFS):
   ・ 意味のある探索経路を発見するために、次の規則を遵守して巡回(DFS 推奨)を実行します。
   ・ **巡回規則**:
   ・ **開始点**: グラフのすべてのノードは潜在的な開始点になり得ます。
   ・ **拡張**: 現在のノード A からノード B への移動は、B が A の `outgoing` リストにある場合にのみ可能です。
   ・ **循環(Cycle) 防止**: 現在の経路シーケンスにすでに存在するノードは再訪問しません (例: A → B → A は無効)。
   ・ **経路の長さ**:
   ・ **最小長**: 5 ノード (幅広い探索のための基本基準)。
   ・ **最大長**: (選択事項, 例: 10) 過度な深さを防ぐため。
   ・ **段階別ロジック (疑似コード)**:

   ```
   変数初期化: PathList = []
   グラフの各ノード "StartNode" に対して:
       Stack = [(StartNode, [StartNode])]
       While Stack が空でない間:
           (Current, Path) = Stack.pop()
           If 長さ(Path) >= 5: PathList に Path 追加
           For 各 NeighborID in Current.outgoing:
               If NeighborID が Path にない:
                   NewPath = Path + [NeighborID]
                   Stack.push((Node(NeighborID), NewPath))
   ```

4. スコア算定および選別:
   ・ 有効な候補経路をすべて生成した後、次の階層に従って "上位" 経路を選別します。
   ・ **経路の長さ (第1順位)**: より長い経路を好みます (より深いユーザーの旅程を意味)。
   ・ **ボリューム指標 (第2順位)**: 長さが同じ場合、高い検索量(`volume`)を持つキーワードが含まれた経路を優先します (より高いユーザートラフィック/関心度を意味)。指標としては経路内の Max(volume) または Sum(volume) を使用します。

5. 検証チェックリスト:
   ・ LLM が経路を出力する際、必ず次の事項を検証しなければなりません。
   ・ すべてのノードペア `(Step[i], Step[i+1])` に対して、`Step[i+1].id` が `Step[i].outgoing` に含まれているか？
   ・ 表示された名前(`name`)が該当 ID と正確にマッピングされているか？
   ・ 経路に重複したノード(ループ)がないか？

## Instructions (指示事項)

・ 核心経路選定 (上位 3つ): 探索された重要経路の中から次の基準で上位 3つの核心経路を選定する。

# ⒊ 構造分析トップ３(Hub & Branch)

[目標]

## 分析段階および指針

1. キーワード分解および意図識別:
   1. name カラムを確認してください。
   2. 各キーワードから「ターゲットキーワード」を識別し、これを除いた残りの部分から **「意図キーワード(Intent Keyword)」** を抽出してください。

2. 概念説明
   1. ターゲットキーワード: 特定製品の名前(ブランドキーワード)、ブランドの名前(ブランドキーワード)、サービスや製品のカテゴリー名(ノンブランドキーワード)、人物の名前、概念であり、主に名詞や代名詞、あるいは名詞形が位置します。
   2. 意図キーワード: 検索語の中でターゲットキーワードと対をなして検索する人の文脈と状況、意図を明確にしてくれる単語や句を言います。形容詞として検索者の意図を示す意図キーワードと言えます。

3. 段階識別:
   1. 「情報探索 → 購買考慮段階へ転換」される地点は次の二つの方法で識別。
      ・ ターゲットキーワードがノンブランドキーワードからブランドや製品へ変化する時点
      ・ 意図キーワードが状態や悩みを確認する段階から検証や購買段階へ移る時点

   2. ブランド中心探索が起きる過程は次の方法で識別。
      ・ ターゲットキーワードがノンブランドキーワードからブランドや製品へ変化する時点

4. 重要度評価およびトップ３選定:
   上記分析を基に最も重要な「転換点」の役割をするキーワード 3つを選定してください。
   選定基準は次の通りです。
   1. 連結性: `edges`が多く、複数の経路へ分岐するハブ(Hub)の役割をするキーワードであること。
   2. 転換頻度: 該当キーワード以後の経路(`edges`)で「ブランド具体化」や「購買段階転換」が頻繁に発生するキーワードであること。
   3. 同一の経路数が現れた場合、検索量(volume)の数値が高いものに優先順位を置く。
