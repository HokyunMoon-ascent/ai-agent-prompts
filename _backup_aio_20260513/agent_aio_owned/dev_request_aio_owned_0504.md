## 1. 문서 개요

### 1.1 목적

본 문서는 `agent_aio_owned` 프롬프트가 정상 동작하기 위해 **개발팀이 채워주어야 할 6개 변수 슬롯**(+ 의도적 미입력 1개)의 데이터 소스, 전처리 규칙, 데이터 형식, 에지 케이스를 정의합니다. 본 에이전트는 `agent_aio_gap`의 출력을 입력으로 직결하는 후속 에이전트이며, 진단을 재수행하지 않고 보강안 3종을 사용자에게 제공합니다.

### 1.2 대상 독자

- 백엔드 개발자 (gap agent 출력 → owned agent 입력 파이프라인 구현)
- 프론트엔드 개발자 (3섹션 마크다운 + 조건부 라우팅 메모 렌더링)
- 프롬프트 엔지니어 (입력값 검증, 자체 점검 체크리스트 매칭)

### 1.3 관련 산출물

- **프롬프트 파일**: `agents/ai_agent/agent_aio_owned/KR/v.0.2.0_aio_owned_KR_0504.md` (현행) / `KR/v.0.1.0_aio_owned_KR_0504.md` (이전 버전)

## 2. 시스템 개요

### 2.1 Agent의 역할

갭 분석 에이전트가 도출한 의미적 갭 결과를 받아, 자사 온드미디어에 즉시 보강·작성할 수 있는 ➊ 필요 콘텐츠/엔티티 리스트, ➋ 페이지 구조 최적화 제안(통합/분리/재구성 재판단), ➌ 구체 샘플 본문(헤더+150~400자 단락) — 3가지 결과물을 사용자에게 제공합니다.

### 2.2 입출력 요약

| 구분 | 항목 |
|---|---|
| **입력** | 갭 분석 결과(4섹션 마크다운) / 자사 페이지 콘텐츠 / AI 검색 질문 / 대화 컨텍스트 3종 |
| **출력** | 3섹션 마크다운 — 필요 콘텐츠/엔티티 리스트(항목별 KBF/RTB 분리 + 페이지 유형 매핑: PDP/FAQ/Blog/Spec/Comparison) / 페이지 구조 최적화 제안(대상 페이지 유형 cross-reference) / 구체적인 콘텐츠 예시(KBF + RTB 동반 단락) + (조건부) 언드 라우팅 메모 |
| **출력 포맷** | `:::accordion` 블록 + `**➊➋➌**` + `:k[..]` 키워드 표기 |

### 2.3 변수 슬롯 매핑 (전체 6개 + 의도적 미입력 1개)

| 변수 슬롯 | 의미 | 데이터 소스 | 비고 |
|---|---|---|---|
| `{{gap_analysis_output}}` | agent_aio_gap의 4섹션 출력 | gap agent 직결 또는 사용자 붙여넣기 | 3.1 참조 |
| `{{page_content_A}}` | 자사 페이지 파싱 콘텐츠 | gap과 동일 세션의 A 자료 | 3.2 참조 |
| `{{user_prompt_B}}` | CEP 기반 AI 검색 질문 | gap과 동일 세션의 B 자료 | 3.3 참조 |
| `{{prev_q}}` | 직전 사용자 질문 | 채팅 세션 상태 | 3.4 참조 |
| `{{prev_a}}` | 직전 어시스턴트 답변 | 채팅 세션 상태 | 3.4 참조 |
| `{{user_question}}` | 현재 사용자 질문 | 채팅 입력 | 3.4 참조 |
| `{{ai_responses_C}}` | (의도적 미입력) | — | 3.5 참조 |

## 3. 변수별 상세 명세

### 3.1 `{{gap_analysis_output}}` — 갭 분석 결과

#### 데이터 소스

- `agent_aio_gap`의 LLM 호출 결과 마크다운(4섹션). 동일 세션의 A·B 자료를 사용한 진단이어야 일관성이 보장됨
- 사용자가 별도 채팅에서 진단을 받은 뒤 결과를 붙여넣기하는 경우도 지원

#### 입력 형태

- 4개 `:::accordion` 블록을 포함한 단일 마크다운 문자열
- 섹션 헤더는 `## 1) 분석 개요`, `## 2) 브랜드 노출 분석`, `## 3) 의미적 갭 매핑`, `## 4) 보강 권장사항` 4개로 고정
- 본 에이전트는 분석 개요(➊ KBF 단서 + RTB 단서)와 의미적 갭 매핑(갭 유형 5분류 + 부족 신호 4축)에서 KBF·RTB 단서를 회수해 Section 1 항목별 KBF/RTB 분리 표기에 활용

#### 출력 형태 (변수에 주입될 형식)

- 마크다운 원문 그대로 주입 (편집·요약·재포맷 금지)
- 인코딩: UTF-8

#### 전처리 요구사항

- 섹션 헤더 4개의 존재 여부 자동 검증; 누락 시 누락 섹션명 메타데이터에 첨부해 프롬프트가 1줄 명시할 수 있게 함
- `:::accordion{title="..."}` 블록의 페어링(`:::` 매칭) 검증
- HTML 이스케이프 미적용 (마크다운 원본 보존)

#### 제약 / 에지 케이스

- 토큰 한계: gap_output + A + B 합산이 모델 컨텍스트 윈도우의 안전권 이내여야 함 (Claude Opus 200k 기준 100k 이하 권장; gap_output 단독은 보통 5~15k 토큰)
- 4섹션 중 1개 이상 누락 시: 본 에이전트는 가능한 항목만 처리 + 누락 사실 1줄 명시
- 갭이 0개인 경우: Section 1·2·3 모두 "처리 대상 갭 없음" 1줄로 출력
- 채널 힌트가 모두 "언드 단독"인 경우: Section 1·2·3 본문 항목 없음 + 라우팅 메모만 출력

#### 미지원 사례

- 다른 버전(v.0.1.0 이외)의 gap 프롬프트 출력은 페어 호환성 표(§6.3)로 별도 관리

### 3.2 `{{page_content_A}}` — 자사 페이지 파싱 콘텐츠

#### 데이터 소스

- `agent_aio_gap`의 §3.1과 동일 (URL 크롤링 결과). 본 에이전트는 동일 세션의 A 자료를 재사용해야 무게중심·톤 분석이 일관됨

#### 입력 형태

- 마크다운 또는 plain text. gap의 입력 형태와 동일

#### 출력 형태 (변수에 주입될 형식)

- gap §3.1과 동일

#### 전처리 요구사항

- gap이 사용한 전처리 결과를 그대로 재사용 (재크롤링 금지 — 시점 차이로 인한 무게중심 불일치 방지)

#### 제약 / 에지 케이스

- gap 세션의 A와 다른 A를 주입할 경우: 무게중심 회수 결과가 갭 분석과 어긋나 통합/분리 재판단의 근거가 무효화됨. 동일성 검증(해시 비교 등) 권장

### 3.3 `{{user_prompt_B}}` — AI 검색 질문 (CEP 기반)

#### 데이터 소스

- `agent_aio_gap`의 §3.2와 동일

#### 입력 형태 / 전처리

- gap §3.2와 동일

#### 제약 / 에지 케이스

- gap 세션의 B와 동일해야 CEP·KBF·RTB 단서 회수가 일관됨

### 3.4 `{{prev_q}}`, `{{prev_a}}`, `{{user_question}}` — 대화 컨텍스트

#### 데이터 소스

- 채팅 세션 상태 관리 시스템 (기존 ai_agent 공통 패턴, gap §3.4와 동일 인터페이스)

#### 입력 형태 / 전처리 / 에지 케이스

- gap §3.4와 동일

### 3.5 의도적 미입력 — `{{ai_responses_C}}`

#### 사유

- 본 에이전트의 핵심 원칙은 **재진단 금지**. AI 응답 원문을 다시 주입하면 LLM이 새 의미 영역을 추출해 갭 분석 결과 외부의 항목을 출력할 위험이 있음
- 갭 분석 결과 본문에 응답 인용(`:k[..]`)이 이미 보존되어 있으므로 C 직접 주입 없이도 인용·근거 추적이 가능

#### 백엔드 가드

- 본 에이전트의 프롬프트 어셈블리 단계에서 `{{ai_responses_C}}` 슬롯이 부주의로 추가되지 않도록 템플릿 검증 필요
- 외부에서 C가 우발적으로 주입되더라도 프롬프트는 입력 파싱 규칙에서 미언급 변수를 무시하도록 설계됨

## 5. 검증 기준

### 5.1 기능 검증

| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| 정상 케이스 | 4섹션 모두 정상 + 채널 mix(온드/언드/온드+샘플) | 3섹션 출력, 온드 포함 갭만 등재, 언드 단독은 라우팅 메모 |
| 갭 0개 | 의미적 갭 매핑이 비어 있음 | Section 1·2·3 모두 "처리 대상 갭 없음" 1줄, 라우팅 메모 미출력 |
| 모든 채널 힌트가 언드 단독 | 통합형/분리형 라벨 모두 채널 힌트 "언드" | Section 1·2·3 비고 1줄 + 모든 갭이 라우팅 메모로 이전 |
| 4섹션 중 1개 누락 | 예: 브랜드 노출 분석 섹션 누락 | 답변 최상단에 누락 사실 1줄 + 가능 항목으로 진행 |
| C가 우발적으로 주입됨 | `{{ai_responses_C}}` 슬롯 외부 추가 | 프롬프트 파싱 규칙이 미언급 변수를 무시; AI 응답 원문에서 새 의미 영역 추출 없음 |
| gap KR 버전 mismatch | gap이 v.0.2 출력을 주입 | 페어 호환성 표(§6.3)에 따른 호환성 검사로 차단; 또는 누락 섹션 처리로 fallback |

### 5.2 출력 품질 검증 (프롬프트 자체 점검 체크리스트와 매칭)

1. 재진단 금지: AI 응답 원문에서 새 의미 영역을 추출하지 않음
2. 온드 한정: 처리된 모든 항목이 채널 힌트 "온드" 또는 "온드+샘플"
3. 통합/분리 재판단: 모든 Section 2 항목에 갭 분석 원 라벨 + AI 재판단 결과 + 근거 1문장
4. 샘플 발명 금지: Section 3 본문에 자사 페이지/갭 분석 결과 외 새 제품명·수치·인증명·외부 사실 없음
5. 출처 강제: 모든 `:k[..]`가 자사 페이지 또는 갭 분석 결과 본문에 실재
6. 페이지 IA 정합성: 분리 결정 항목에 H1/H2 트리와 페이지 목적이 모두 있음
7. 샘플 길이 준수: 모든 Section 3 본문이 150~400자 범위
8. 용어 표기 규칙: A/B/gap_analysis_output/consensus/variance 같은 내부 라벨이 출력에 노출되지 않음
9. KBF/RTB 분리: 모든 Section 1 항목에 충족 KBF·뒷받침 RTB가 분리 표기됨, Section 3 본문에 KBF 1개 + RTB 1개 이상 동반 제시
10. 페이지 유형 매핑: 모든 Section 1 항목에 PDP/FAQ/Blog/Spec/Comparison 중 1개가 매핑되고 Section 2에서 cross-reference로 다시 표기됨
11. 정보 구조 정렬: 본 에이전트가 카피라이팅이 아니라 정보 구조 정렬 결과를 산출했는지(단일 메시지 "○○는 좋습니다" 형태 미산출)
